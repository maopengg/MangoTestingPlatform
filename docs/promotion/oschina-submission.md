## 完整项目介绍

### 项目背景

许多团队的自动化建设从个人脚本起步。随着项目和用例数量增加，测试资产容易分散在多个仓库与工具中，环境和账号配置被重复维护，测试数据依赖人工准备，执行失败后的日志、截图、请求响应和报告也难以形成统一链路。

芒果测试平台希望将测试信息配置、自动化资产、测试数据、执行调度和结果分析放进同一个系统，让自动化从“脚本能跑”逐步变成团队可以持续维护的质量资产。

### 核心能力

> 当前软件库资料同时包含公开版本和最新版预告。公开仓库未包含的能力均在下文标注为“最新版”。

#### 研发协同与质量效能（最新版）

- 以迭代、需求、开发设计、功能用例、测试计划和缺陷组织研发测试过程。
- 功能用例支持连续编辑、版本历史和自动化资产绑定。
- 汇总执行趋势、失败原因、测试进展和风险待办，并能回到原始数据来源。

#### API 自动化

- 管理接口定义、请求方法、URL、请求头和多种请求体。
- 支持多步骤用例、场景参数、变量引用和执行顺序维护。
- 支持响应提取、JSONPath、文本、Schema、状态码等断言方式。
- 支持前置与后置 SQL、自定义函数、等待和重试。
- 保存请求、响应、断言和失败详情，便于回溯执行过程。
- 最新版增加接口与用例版本管理、模块覆盖流程和 Mock 服务。

#### UI 自动化

- 按页面、元素、步骤和用例组织 UI 测试资产。
- 支持 Web、Android 和 PC 桌面自动化场景。
- 支持录制、步骤编排、断言、失败截图和日志回传。
- 通过独立执行器承接需要特定系统或浏览器环境的任务。
- 最新版增强实时工作台、元素检测、智能定位和可审查的自愈流程。

#### Pytest 管理

- 管理 Pytest 测试项目、文件和用例。
- 支持用例发现、执行调度、结果收集和报告查看。
- 帮助已有代码型自动化资产接入统一的任务与报告体系。

#### 测试数据工厂

- 使用逻辑数据源映射不同测试环境的真实数据库。
- 根据数据库表结构维护业务实体和字段生成规则。
- 通过状态模板表达一类可复用的业务测试数据。
- 用例执行前自动造数，并通过变量引用生成结果。
- 记录数据创建过程，并在执行结束后按策略清理。

#### 调度、执行与报告

- 支持测试套件、定时任务、远程执行器和 API Worker。
- 跟踪任务分发、执行状态、失败信息、日志与截图。
- 从用例、步骤、断言和请求响应等维度查看报告。
- 支持历史记录追踪，帮助定位回归失败原因。

#### 性能测试与工程治理（最新版）

- 支持性能场景、测试计划、运行历史、分阶段负载与执行器容量管理。
- 支持灰度仓库、配置文件、开关和执行记录管理。
- 统一 SQL 执行审计、用户操作日志，以及前端、服务端和执行器异常记录。

#### MCP 与 AI

- 通过 MCP 向 AI 助手提供结构化的平台能力。
- 支持查询项目上下文、测试环境和现有测试资产。
- 支持在权限范围内维护自动化配置、触发执行和读取报告。
- 将 AI 生成内容与平台中的真实资产和执行结果连接起来。

### 技术架构

```text
mango-console      Vue 3 + TypeScript Web 控制台
MangoServer        Django REST 后端与业务服务
MangoActuator      UI、Pytest 等任务的独立执行器
Scheduler Service  定时触发和任务分发
API Worker         API 自动化任务执行
MCP Service        向 AI 客户端提供平台能力
MySQL              配置、资产和执行索引数据
MinIO              截图、附件和大文件存储
```

项目提供 Docker Compose 编排，可按文档部署 Web 控制台、后端、调度服务、API Worker、MCP 服务、数据库和对象存储。

### 适用场景

- 团队级接口回归、UI 回归和 Pytest 统一执行。
- 多环境测试配置与自动化资产复用。
- 复杂业务状态下的测试数据准备和清理。
- 定时冒烟、周期回归与失败报告追踪。
- 私有化建设企业内部测试平台。
- AI Agent 与测试资产、执行任务和报告分析集成。

### 项目特点

- 不局限于单次接口调试，强调团队资产和持续执行。
- 不只管理用例，将测试数据准备和清理纳入执行闭环。
- 配置型自动化与 Pytest 代码型资产可以并存。
- 执行服务与 Web 服务拆分，支持独立 Worker 和执行器。
- MCP 让 AI 能够理解并调用真实平台能力，而不是只生成孤立脚本。
