# API Case 创建与维护

## 适用范围

**API Case 与 API Info 发布流程必须分开：** API Case 最多提交 `预发布`，即使具备正式发布权限也不得代用户审核发布；定时报告修复同样遵守。API Info 没有 Case 的预发布审批流程，在已授权创建/修改范围内，自检和验证后生成修订并直接发布，不额外请求用户审批；仍须具有接口发布权限，无权限则保留已验证修订交接，不绕过权限。

根据请求和已核实的平台状态选择：

- **创建：** 将权威 curl、API 文档、源码契约、业务场景或代码驱动 Skill 的已确认交接转成可执行 API Info/API Case。
- **修复：** 按精确 Case ID 或无歧义的产品/模块/名称修正已有 Case，保留全部覆盖。
- **复用扩展：** 相同契约复用精确匹配的 API Info/Case，只补缺失场景或配置，不重复创建。

本 Skill 不盘点后端接口或设计新覆盖，不从执行报告/任务选失败项，不上传诊断 Markdown，不重试报告行、整报告或任务。请求源自定时 API 报告时，使用 [定时报告修复 Skill](../mango-scheduled-api-report-maintainer/SKILL.md)，由其负责范围、授权、发布和原失败行精确重试；它不适用于手工/临时报告。

平台操作只走 mango-test-platform MCP，禁止平台 SQL、ORM、shell、直连 HTTP 或后端 service 绕过读取/修改平台元数据。缺安全能力则停止对应操作并报告。需要数据工厂时，完整读取 [数据工厂 Skill](../mango-data-factory-builder/SKILL.md) 及其按操作路由的参考资料。

涉及 API 新建 SQL/ES 资源、负向创建可能意外落库、重复名称、删除后的索引残留或历史清理失败时，必须先读 [API 创建资源的编写与清理](references/api-created-resource-cleanup.md)，再读取当前 MCP 的 `get_api_case_resource_cleanup_schema` 和工具签名。不能沿用旧执行“平台不支持数组”的结论，也不能把“代码已支持”当作目标服务已部署或 Case 已配置。

## 必要上下文

只提供接口或附带代码时，遵循 [独立预期规则](../mango-test-case-document-builder/SKILL.md#interface-only-input-and-independent-expected-results)。curl 只说明发请求方式，不证明所有正确业务结果。保留来源或代码驱动交接的业务基线和预期依据，用代码解析触发/数据与补漏，不以实现证明自身正确；不复制调试响应生成预期，不将代码现状候选悄悄升级为业务验收。代码未实现但有依据的预期也要保留；不明确的列问题/候选，不猜断言，继续有独立依据的 Case。本规则不扩展为模块覆盖设计，也不绕过方案、数据、安全或发布门禁。

修改前确定：

- 项目产品、模块；
- `scenario_layer`：0=接口/组件级（单个接口或组件），1=模块级（同一模块内多个接口、组件协作），2=端到端（跨多个模块的完整业务链路）；名称不插空格，值不变，不因多步骤、工厂或SQL自动升级层级。
- 可访问且适合构建和完整验证的环境；
- 根据业务目的、副作用、依赖、清理和生产安全推导的执行场景标签；
- 已确认交接、curl、API 文档、controller/DTO/service、报告/运行详情或历史通过等权威契约证据；
- 创建时的名称、场景、预期、数据前置及清理要求；
- 修复时的精确 ID、当前编辑态/发布修订和观察到的问题。

产品/模块/Case/契约有歧义时只问缺失标识或证据。当前环境是可切换执行上下文，不是 Case 固有属性，不能因此省略、延期或拒绝有效 Case。切换到可访问的合适环境验证；仅没有安全可执行环境，或身份/配置差异重大且无法推断时才问环境。

## 环境与执行场景

分别理解：

- Case 定义可复用业务场景、请求、断言、前置及清理；
- `scenario_tags` 决定哪些执行用途和环境类别可选中它；
- 环境选择器决定本轮调试/验证位置，可按需切换。

按完整 Case 树而非当前环境打标。适合非生产时选 `routine_regression`、`release_verification`、`smoke_verification`、`data_verification`；只有完整 Case 符合生产边界才加 `production_inspection`、`production_regression`、`stability_monitoring`。兼容标签可多选。

历史或当前生产风险不妨碍安全的非生产创建。写操作、工厂、SQL、夹具、破坏性动作及清理若在测试环境完整安全，就在该环境创建验证，只打适合的非生产标签；不得仅因不适合生产就置为 `deferred`、留下 `0/0` 或要求固定环境。`temporary_validation` 仅用于真实的一次性诊断/实验，不能代替稳定测试 Case。切换环境不授权不安全写入或绕过清理，也不授予生产标签资格。

### 执行场景审核硬门禁

每个 Case 创建、完成和提交前都须审核标签。禁止全模块套默认标签，也不能只凭名称、HTTP 方法、当前环境或一次通过来判断。

读取最终完整树，在工作证据中逐一审核所有支持标签，记录 `适用/不适用`、具体依据和安全条件。至少选一个，仅保存已证明适用的标签。审核业务目标/关键性、请求语义、身份权限、前置、SQL/工厂、持久/异步副作用、隔离、清理恢复、断言和调度用途。

最低判断：

- `routine_regression`：稳定可重复业务回归，前置/断言确定，清理或恢复完整。
- `release_verification`：发布门禁、变更影响、兼容性或明确审核的发布后验证；普通回归不自动满足。
- `smoke_verification`：精选少量关键入口/主链路，失败会阻断基本可用性；不得所有成功 Case 都标冒烟。
- `data_verification`：测试目标为持久化、计算、筛选、聚合、映射或前后状态一致。
- `production_inspection`：完整流程证明生产安全且只读无副作用。任一步使用 `PUT`、`PATCH`、`DELETE`、数据库写、SQL/工厂或业务状态改变均拒绝；`POST` 必须有完整只读证据，不能凭方法名或当前行为认定。
- `production_regression`：明确批准的生产业务操作，整体隔离、幂等或可靠可恢复。含任何 SQL、生产数据库连接或工厂均拒绝。
- `stability_monitoring`：目的是确认生产服务持续稳定可用，及时发现服务不可用或关键功能异常；通过高频只读巡检实现，例如每分钟检查一次关键功能，频率由定时任务配置。断言须验证服务或关键功能实际可用，不仅检查请求已发出。区别于常规周期的 `production_inspection`，不能仅因只读而默认添加。必须轻量、可持续重复、断言稳定、负载有界，无业务副作用且不累积数据或漂移，并有完整生产安全证据。
- `effectiveness_test`：AI、算法、搜索、排序或生成质量目标，且有明确质量判定。
- `temporary_validation`：真实的一次性排查、诊断、实验，不用于规避稳定设计。
- `performance_test`：有明确吞吐、并发、时延、容量或资源目标与性能执行设计；普通功能重复不满足。

请求、方法、步骤/场景、身份、前置、SQL/工厂、副作用、断言、清理或调度目的变化，原审核失效，须按完整树重审。仅分类修改可保留 Case 身份，但完成/提交前仍需重审。

保存后回读 `scenario_tags`，与审核集合精确一致。生成不可变修订及预发布前再次读取完整编辑态，将审核绑定到该候选/修订。无审核、空标签、不支持标签、无适用依据或违反生产边界时，禁止完成、修订提交、预发布及正式发布。不能先发布后改标签。

## 业务数据必须运行时解析

可复用 Case 禁止嵌入某环境的固定业务数据：记录 ID、用于选存量的名称/编码、租户/用户/组织/部门/角色身份、订单、文件、模板、流程/任务、绑定某记录的日期及环境业务预期值。检查请求、头、变量、断言、脚本/SQL、前后置、工厂模板及覆盖值；表达式内隐藏字面量或固定名称查询仍是固定依赖。历史通过或“稳定夹具”不构成例外。

允许全局/公共变量及授权管理上下文，但必须保留平台运行表达式，按当前环境/身份解析并核验租户、归属、状态、类型、可见性和场景资格。不将解析值粘进资产、不跨环境复用同一环境值、缺变量不回退记忆值。全局变量可以提供环境维护前置，但不授权改删共享数据。

其他业务值运行时通过合格只读 API、允许的只读 SQL、响应提取/缓存或本轮隔离 API/工厂造数获取。查询必须证明资格，而非随便取一行。删除和清理仍只作用于本轮创建数据，不得删除全局变量或查询取得的共享对象。缺数据要构造或报告前置缺口，不硬编码。

契约常量可固定：枚举、分页、空/null、故意非法格式、已证明不存在的边界值。必须服务于测试目标，不依赖环境存量或误选真实记录。环境地址/凭据放环境和授权配置，不内联到 Case；平台资产 ID、固定修订是元数据，不是禁止的业务前置。

创建/更新、回读、完整执行和提交前记录业务值运行来源，确认无环境固定依赖。修旧固定值须保留业务目标，不因固定数据通过一次就称完成或提交。

## SQL 性能与数据库负载门禁

本规则适用于本 Skill 编写、修改或执行的所有获准业务 SQL，包括前置查询、SQL 变量、断言、后置清理及为该 Case 排查问题的临时 SQL。只读不代表没有数据库压力；原有环境、授权和数据归属边界不变，尤其不得因此在平台配置生产 SQL。

- **先缩小访问范围：** 从原测试目标推导完整资格条件，尽早使用租户、已知主键/关联 ID、本轮唯一键、必要状态及有依据的时间范围过滤；只取需要的字段和最少合格样本。优先精确索引查询，避免大范围多表关联、重复子查询/扫描、全量计数、无界排序、随机排序及对索引过滤列施加函数或隐式类型转换。不得靠任意截断候选、随意缩小日期或删除资格条件换取速度，导致原场景无法验证。
- **执行前检查访问路径：** 结合真实表结构、索引、关联基数及数据量检查 SQL；大表、复杂关联、聚合或排序语句先使用目标数据库支持且获准的非执行型 `EXPLAIN`。`LIMIT` 只限制返回行数，不证明扫描量小或执行快。不得为“看执行计划”直接执行 `EXPLAIN ANALYZE` 等会实际运行高风险 SQL 的命令；不得擅自新增索引、修改数据库参数或扩大连接权限。
- **小范围实测后再接入：** 在允许环境中，使用真实运行参数或等价的受控数据，先单条、串行验证，记录环境、耗时、返回/影响行数和可取得的计划证据。默认以秒级完成为目标，沿用已有单条 SQL 超时、数据库慢查询阈值及 Case 总耗时预算，取适用的更严格限制；不能将“低于 20 秒”作为所有 SQL 的通用合格线，也不能仅凭缓存命中时的一次快速结果证明稳定。没有测量或无法证明访问范围可控，不称性能验证通过。
- **禁止用超时和重跑掩盖慢查询：** 发现历史慢 SQL、超时、明显大扫描、异常排序或超出预算，停止该语句的重复及并发执行，先优化访问路径或改用合格只读 API、本轮隔离数据/工厂前置。优先复用同轮安全查询结果，避免每个步骤/场景重复扫描；不得提高超时、增加重试或并发试跑来刷通过。工具支持时设置查询超时；客户端超时不等于数据库已停止执行，应核实运行状态，取消操作只使用已有授权能力。
- **清理同样必须快且精确：** 通过本轮精确 ID/唯一键和必要租户条件定位，按依赖顺序执行，不用全表模糊查找或宽泛删除。写 SQL 不得为测速重复执行，须在原数据归属、清理授权和失败安全规则内验证。
- **提交前必须过门禁：** 保存回读最终 SQL，确认实测的是同一版本，既查到满足全部资格的样本/得到正确断言结果，又满足耗时与负载要求，并在完整 Case 中检查重复调用次数、调度频率及并发的累计压力。SQL、过滤条件、关联、调用次数或主要数据规模变化后重新评估。未通过先继续优化对应 Case，不提交预发布、不称编写完成，其他独立 Case 可继续；不能为性能优化修改测试目标、提示词或放宽业务断言。

工作证据保留优化前后 SQL 差异、访问范围/索引依据、耗时和样本有效性；用户汇报只需简述主要优化及实测结果，不输出凭据或敏感数据。

## 名称与场景描述硬检查

包括其他 Skill 交接的 Case，创建前检查名称/描述与确认的测试意图一致。名称自然、准确、普通测试可理解，不与 API/场景/断言矛盾；可保留有追溯价值编号及必要区别条件/结果。产品、模块、客户端、环境、执行场景若只是元数据则移除前缀。不得用方法名、脚本标识、维护说明或技术标签串当名称。

场景描述必填，普通业务语言明确“具体测什么”，无需解码编号或阅读请求、断言、源码就理解条件与行为。输入、前置、来源编号、数据约束、执行说明可作为补充，不能代替测试点。仅编号、自动化 ID、接口/参数名、技术词或 `正常场景`/`异常场景` 等泛述不合格。不强制句式、不编事实。保存回读再查，空白、仅编号、含糊或技术化难懂时修正后才能完成或提交。

## 代码驱动的配置禁写

代码驱动来源或交接必须先读并遵循 [配置禁写边界](../mango-code-driven-api-case-builder/references/automation-boundaries.md#mandatory-configuration-write-exclusion)。禁止创建、扩展、复用、绑定、调试、执行或发布会修改环境/服务运行配置、系统/租户管理控制、额度/权益或授权设置的 Case，覆盖所有正负场景、前置、工厂/SQL/脚本、间接/异步副作用及清理恢复。规则库规则、规则组、清单、业务模板不因可复用、租户归属或“配置/管理”名称而排除；其隔离 CRUD 必须有范围、归属、业务断言和失败安全清理证据，按真实写路径与影响分类。

修改前查明代码副作用，调试、执行、建修订和提交前重查完整树。预期失败、测试环境、隔离数据、事后恢复或全覆盖要求不豁免。查询配置仅在全流程无写入时允许；普通隔离业务写和平台自动化资产编辑按各自规则，不属于此禁写。

业务场景依赖改配置时，只读使用现成合适配置，或交回台账注明排除，不改环境来补前置。已有排除资产仅报告，不执行、不静默删除/解绑/改状态；不请求二次确认绕过。此来源限定规则不扩展独立请求为配置测试，也不授权一般安全边界所禁操作。

代码驱动的角色、权限、授权管理只查询。禁止创建、编辑、删除、启停、复制、导入、重置角色/权限，授撤权限、绑解菜单/数据范围、分配/移除用户角色、修改授权成员关系；包括临时隔离对象、预期拒绝请求、前置、工厂/SQL/脚本和恢复。业务权限测试只能用已有合适身份，不改角色权限；没有身份则排除对应场景，不修改授权。

## 方案与确认门禁

### 代码驱动交接例外

已核实的代码驱动交接默认 `接口已完成，按严格断言执行`，不再问下方就绪选项。用户明确仍开发则尊重，但两种模式都保留严格契约断言；默认不代表 Case/执行已完成或通过。

用户已明确要求真实创建、执行或完成确定范围时，交接保留授权；方案作为进度呈现并冻结范围，不再泛问是否开始或接口是否完成。仅扫描/设计、授权未明确或重大扩围不适用；契约、身份、隔离、清理、标签、发布权限及破坏性操作门禁仍有效。其他来源走普通确认流程。

从用例文档、API 清单、飞书/Excel、curl、设计、代码契约或流程新建时，将只读调研与平台修改分开。确认前只可解析来源、查资产/配置、确定归属/环境/负责人、读契约证据和拟方案；禁止创建更新 API Info、Case、步骤、场景、头、变量、工厂、前后置、执行、修订、发布或外部追踪记录。

修改前给结果导向的具体方案：

- 来源/范围、筛选规则、已知场景数与首批场景；
- 产品/模块、建议验证环境、标签、负责人/测试人、客户端和权威来源；
- 接口契约与 API Info 复用/创建/更新判断；
- 场景分组分类、请求差异、数据/前置、头、提取器、业务断言和清理；
- 执行、发布和外部回填边界；
- 将创建/修改的资产、假设、未决缺口和重大风险。

最终仅集中一次给出 `请确认信息` 表，列 `项`、`当前识别结果`，值标 `已识别`、`建议采用` 或 `需确认` 并说明依据，只问更正或真正阻塞，不多处重复。

新多场景文档按数量/分组概括剩余范围，不逐行罗列。建议先做1–2个代表 Case，通常主成功路径加有实质差异的负例、边界、权限或数据路径。

非代码驱动例外的独立创建，在信息表后要求一次编号选择：

1. **接口已完成：** 严格断言，按请求、数据、断言、清理、环境、平台、产品证据排查失败；开始代表 Case。
2. **接口仍在开发：** 依权威契约构建，可保留失败，但不为通过放宽断言；开始代表 Case。

用户只说 `开始` 或明确授权首批但未选就绪状态，默认1并记录。修改前等待明确确认。`跳过方案`、`直接开始`、`直接全量` 等明确授权可在该范围跳过门禁，记录后不重复询问。

确认方案成为冻结清单。接口映射、场景范围/数量、标签资格、安全类别、身份、数据、副作用、清理、发布或回填发生重大变化，影响操作前展示差异并再确认。同安全类别内切验证环境，且身份/数据/副作用/清理/范围不变，是常规上下文切换，不重问。

方案已明确允许编辑已有 API Info 后，不因它已发布而二次确认；只改调试编辑态，不改旧修订、Release 或固定版本步骤。MCP 需预览/token 时，在原授权下核对影响与冻结清单完全相同后使用，不打断；目标或影响扩大仍再确认。

达到完成门禁的 Case 必须走下文提交流程，不把提交/发布作为可选后续选择。方案说明预期交付，不再让用户决定合格 Case 要不要提交。定时报告直接修复已有授权按其范围/修改/发布规则，不再要创建方案。

## 安全边界

- 修复扩展保留已有 Case、步骤、场景/参数、请求分支、断言、提取、前置、清理和工厂覆盖。
- 创建保留每个确认来源场景及独立业务判定，不合并成泛化通过场景。
- 泛称 `修复` 不授权删除、停用、解绑、合并、跳过、`allow_failure` 或放宽断言。
- 仅权威契约证明旧预期错误才能改断言。
- 不改后端代码、部署、租户权限、生产配置或第三方。
- 执行运行时数据硬门禁，即使看似稳定也不得固化环境数据或展开全局变量为字面值。
- 任取第一行（`content[0]`、`LIMIT 1`、`TOP 1`）必须已证明完整资格与确定排序。
- 破坏性/有影响 MCP 修改先预览并按工具使用 token。冻结清单内精确授权不重复问；影响新增或扩大则确认。

## 前后置函数：优先现有配置

**请求头选择：** 默认开启的请求头无需重复勾选。编辑态中，场景 `headers` 非空时仅使用场景所选项；否则使用 Case `front_headers`，Case 也未选时自动使用当前产品默认开启项。显式选择是整体替代，不合并上层或默认请求头，与全局变量的加载规则不同。执行已发布、预发布或指定 Case 精确修订时使用该修订冻结的请求头快照，管理页后续修改不会更新旧快照；其中 `${{变量}}` 仍在运行时替换，不是冻结 Token 值。保存后回读所选 ID，完整执行时核对最终请求。

创建或修复前先读 `get_api_case_schema`；能用平台配置表达就不写函数。简单或嵌套 JSON 直接填匹配接口类型的 `body_config`，动态值用 `${{变量}}`/已登记的数据方法；不得仅为构造、序列化 JSON 或原样返回请求/响应添加函数。查询前置接口用有序步骤，响应取值用 JSONPath/正则提取，常规验证用断言配置，造数与清理用获准工厂及 SQL，不将这些藏进脚本。

- **前置 `front_func`：** 仅用于平台配置、变量和现有数据方法无法表达的请求计算或编码，例如接口特有签名；每场景前置 SQL 后、请求前执行，接收 `(self, request)` 并返回 `ApiExecutionRequest`。
- **后置 `posterior_func`：** 仅用于现有提取/断言无法处理的响应解码或派生计算；在响应提取、场景后置 SQL/等待之后、文件处理和断言之前执行，接收 `(self, response)` 并返回 `ApiExecutionResponse`。取得响应不等于业务成功，保留原始响应证据，不改状态码/业务字段、不吞错或伪造结果来通过断言。
- **失败清理：** 场景 `posterior_*` 依赖请求返回且前序后处理成功，不能作兜底。API 新建 SQL/ES 资源优先用 Case `resource_cleanup`，工厂只清其拥有的数据；仅 SQL 副作用可用已证明失败安全的 Case 级 `posterior_sql`，不能用它冒充 ES 清理。需业务 API 撤销且没有失败安全编排能力时记录能力缺口，不用场景函数或最后一步冒充 finally；生产仍禁 SQL/工厂，不扩大写授权。

函数使用前记录“现有配置缺什么、函数负责什么、输入输出及副作用”，无必要则留空。保存回读并完整验证请求、原始响应、断言与失败清理；修改已有冗余函数时保留类型、动态值、测试意图和断言强度，不批量删除未审计脚本。

**禁止将函数作为默认保护模板：**

- 普通 Header、语言、Cookie 和认证选择使用请求头/授权配置；固定参数、路径变量、简单 JSON 增删字段及缓存赋值使用对应原生配置，不为这些单独添加函数。未认证场景须确认最终请求确无凭据；现有配置不能表达时只保留最小必要处理并记录缺口，不直接移除保护。
- 不在每个场景复制 JWT 解码、固定 URL/Method 检查或环境检查。身份资格优先用既有授权上下文及可信身份查询步骤核验、提取，再以原生断言检查；JWT 解码不等于验签。只有场景特有且无法原生表达的校验才保留，安全条件变化仍须重新核验。
- 协议通用检查遵循下文“协议默认断言不重复”，场景特有状态使用平台已支持的预期调用结果配置；业务字段、类型、空值及常规集合比较用原生断言，取值用提取器。禁止用后置函数只写状态码断言、缓存原响应或原样返回；不得把整个业务判定藏进后置函数，导致原生断言为空。能力未暴露则记录具体缺口，不猜字段。
- 递归树、跨结果关联或复杂动态表单等先拆出可原生表达部分，剩余确需脚本的计算单独说明；不能因其中一项复杂，就把请求、全部断言和清理都迁入函数，也不以“加强保护”免除必要性审核。

## 数据归属与强制清理链

Case 涉及的每条持久数据都纳入一个清理设计，即使由不同组件创建：

- 工厂只拥有其执行记录中的行。
- Case 拥有被测 API 新建的子行、关联、审计/业务或引用工厂数据的异步结果；必须显式清理，不能指望工厂自动发现。
- 场景获准修改已有行时，必须设计同等可靠的恢复/撤销。

例如，工厂建角色，API 建关联用户，只删角色不够；须捕获本轮用户 ID 或唯一键，在 Case 后置先删用户及其关联，再由工厂删角色。

这是构建与提交硬门禁：

1. 根据权威契约盘点每个写场景直接/下游持久副作用，记录创建方、精确身份获取及清理恢复。
2. 请求、提取、断言或后续步骤失败也必须执行的清理，放 Case 级后置；响应后处理可能不执行，不能作兜底。
3. 按依赖顺序：API 后代/关联 → API 父行 → 工厂子行/根行。
4. 删除限定本轮返回 ID 或合法 `AUTO...` 唯一业务键加必需租户条件；不得仅宽泛外键、名称、时间段或共享工厂根删无关数据。
5. 清理幂等：已不存在为成功，连接/权限失败仍显示失败。

API 创建的 SQL/ES 资源按 [编写教程](references/api-created-resource-cleanup.md) 配置原生 `resource_cleanup`，不登记为工厂创建；保存完整规则列表并回读。区分 SQL 自增主键、业务 ID、ES 文档 ID 和业务版本，负向场景也必须覆盖意外创建。业务断言与清理判定独立：业务失败但清理成功仍失败，业务通过但清理失败不能提交预发布。

候选最终审核及 `update_api_case_publication_status(target_status="prepublished", revision_id=...)` 前，MCP 回读完整编辑态，对照已保存 Case 后置和工厂绑定核验副作用清单。消费工厂数据后 API 创建行无精确、失败安全清理时 Case 不完整，不提交，先补清理或报告阻塞。MCP 看不到足够配置则报能力缺口，不提交。包括定时报告修复在内，Case 均止于预发布，正式发布交用户在页面手动完成；API Info 验证后可直接发布。`target_status="unpublished"` 为驳回，不属于成功构建流程。

## 生产边界

PROD 或标记 `生产巡检/生产回归` 的平台资产/执行：

- 修改与执行前读完整树；
- 禁止所有 SQL 查询/写/断言/清理、生产数据库连接/配置、工厂及数据库直接修复；
- 巡检仅无副作用的查询/计算/校验/预览；
- 回归可用获准的正常产品 API 做业务变更，但仍不能含 SQL、生产连接或工厂；
- 不为可执行而静默跳过被禁前后置。

违反时报告精确计划项或 Case/步骤/场景/配置 ID；未经明确授权且保留覆盖的安全重设计消除风险，不创建、不执行、不发布。

平台禁令不扩大为本地只读诊断禁令。本地已有有效生产连接时可用任务相关只读 `SELECT` 作外部证据；不在平台建/存连接，不将凭据写 Case，不执行生产 insert/update/delete/merge/truncate/DDL、可写过程、权限或其他修改。

## 创建或修复流程

### 1. 确定对象与基线

创建在只读调研中拟清单，按方案门禁呈现，确认或适用代码驱动例外后冻结。包含契约、场景、请求差异、断言、前置、提取、清理、环境、标签和归属。先查现有 Info/Case，仅精确契约复用，不重复。

修复/扩展读完整编辑树和已发布修订，记录 Case ID/名称/状态/标签/任务绑定；步骤 ID/顺序/Info ID/固定版本；场景/参数 ID/名称/顺序/状态/数量；params/body/files、公共头变量、断言、提取、前后置及工厂。保留逐对象标识，不只总数。清单/快照是执行提交前的覆盖基线。

### 2. 验证设计或诊断失败

创建逐场景核对权威契约，明确请求差异及至少一个可区分业务错误的断言，传输成功/非空不够。

修复读最新相关单 Case 结果，适用时运行平台失败分析，依次比较：真实请求响应错误；Info 方法/URL/协议/体类型/绑定版本；参数/类型/提取/缓存；前置资格和清理；文档/源码/历史通过；环境、身份、外部依赖、执行器。原因分为请求构造、断言、缓存提取、前置数据、工厂、清理、认证环境、后端缺陷/契约变化、外部依赖、平台执行器。

只在证据充分时修；当前响应本身不是权威契约。预期与实际不符时：

- **契约明确：** controller/service 明确，权威文档或维护测试与代码一致，目标环境也一致，且修改不削弱安全、权限、租户及业务边界，按过时 Case 正常修复/回读/完整执行/版本提交。
- **契约冲突或缺失：** 代码、文档、需求、前端、测试、环境不一致，或改变安全边界；保留断言并列证据，询问缺失决策。

多方一致时不能泛称不可修；单次成功或失败不能当权威。

### 3. 最小正确资产变更

创建：

1. 按产品、模块、客户端、方法、规范化 URL、协议/体类型和归属查 Info；已证明路径参数的 `{name}` 与 `${{name}}` 比对时统一为 `{name}`。
2. 精确匹配复用，否则按证据创建回读。仅所有值可在 Info 作用域解析时用 `run_api_info`；独立调试只验证传输，HTTP 200 即通过，业务断言留 Case。
3. 查等价 Case，无等价资产才创建。
4. 按清单添加有序步骤、场景、请求、断言、提取、前置、清理及获准工厂绑定。
5. 每个对象回读并记真实 ID，不能仅请求成功就报创建成功。

修复常见安全修改：参数/body/files 位置和 JSON 类型；过时固定 ID 改合格动态前置；变量/提取路径和缓存；恢复权威业务断言；修 Info 协议/体类型并验证，具备接口发布权限时直接发布该修订，无权限则交接；过时 Info 固定版本重绑；工厂/场景清理；符合契约判断且保留原安全业务覆盖的旧请求/断言更新。

Info 协议/体类型变化时：快照 Info 和引用步骤 → 修改回读编辑态 → 无 Case 专属运行变量时独立调试只要求 HTTP 200 → 自检接口契约、精确变更和引用影响后生成修订并直接发布，回读 Revision/Release；无权限保留修订交接→ 检查步骤是否仍固定旧 Release。

代码证明的路径参数必须存平台语法：`/cooperation/{cooperation_id}` 转为 `/cooperation/${{cooperation_id}}`。只转路径 token，不转查询、body、表达式或任意大括号，不重复包装既有 `${{...}}`。验证前由获准变量、提取或前置确定写入同名缓存。已有等价 Info 用框架语法时复用并正常编辑/版本化，不因语法差异新建重复 Info。

仅 Case 前置、提取、场景或缓存提供的值在 Case 执行时校验，不在独立 Info 调试强校验。`run_api_info` 有缓存就替换，无缓存按原 `${{variable}}` 发出；不当作清单漂移/平台阻塞，不为调试建启公共变量或改契约变量名。Case 与授权管理仍严格缺变量即失败，最终替换、业务断言和清理由完整 Case 验证。

MCP 为改固定 Info Release 需替换步骤时，先精确预览影响，按原顺序重建，完整恢复场景、断言、提取、前后置及绑定；无法证明全部恢复则停止，不发布 Case。

### 4. 正确构造前置数据

从场景反推租户、用户/角色、归属/协作、类型、状态、有效/删除、流程节点、必需子行/文件及权限。先按操作定策略：

- **查询：** 可只读 API 查真实字段和合格记录，再精确筛选；独立验证包含/排除，不能复制发现响应当筛选正确证据。
- **创建：** 可查询满足租户/归属/状态/权限的共享前置；只读不授权改删，仅清本轮新行/关联，不删共享前置。
- **删除：** 禁止 API/SQL 查存量选删除目标，避免删他人和数据耗尽。每轮先经业务 API 或允许测试环境工厂造隔离目标，捕获精确 ID；查询只确认本轮目标或删除结果，不从存量补目标。不限 HTTP 方法，含逻辑/批量删；批量只能本轮，范围无法保证则不执行。造数失败/目标缺失不回退共享历史。删除/断言失败遗留也要有兜底清理，成功用只读查询或获准数据库断言验证。

获准只读发现/前置优先级，不覆盖删除归属规则：

1. 可证明全部条件的安全只读产品 API；
2. 仅获准非 PROD 的平台只读 SQL；生产诊断可用本地已有授权连接只读 `SELECT`，不复制进平台；
3. 数据库可表达状态用工厂；
4. 不可替代流程/外部状态用正常 API 加可靠清理；
5. 否则记录创建/修复阻塞。

确定性排序，长 ID 在诊断/脚本边界按字符串，防精度损失；不复制其他环境可变 ID。

写请求消费工厂值时，追踪 API 可能新增的数据，优先响应捕获 ID，否则已证明本轮唯一键。每个 API 后代/关联都补 Case 级后置，先于工厂执行结束清理；仅工厂绑定有效不算完整。

### 5. 有效断言

**协议默认断言不重复：** 先回读“启用协议默认断言”及当前协议实际勾选的检查项；开启且已覆盖的通用检查（如 HTTP/SSE 2xx、GraphQL errors 为空）不再逐场景用函数或原生断言重复。不得默认添加 `assert response.code==200 and response.json.get('code')==200 and response.json.get('success') is True`；不把响应信封字段作为所有接口的固定模板。

显式预期优先：确需精确状态或负向响应时按契约配置场景预期，不被默认成功规则覆盖。开关关闭、未勾选或无法核实时，不能假设已检查，也不擅自开启全局设置；按测试目标补必要的原生预期/断言。HTTP 2xx 不等于业务 `code=200/success=true`，这些字段仅在契约及本场景确需验证时配置，仍须验证具体业务结果，不能因默认断言存在而省略。连接、超时或后处理异常仍是失败，不用脚本吞错。

区分 HTTP 绑定/网关4xx与 HTTP 200 业务错误封装，保持 JSON 类型，使用平台支持方式。每场景至少一条证明命名业务行为的断言：若接口忽略条件随便成功，至少一条必须失败。筛选、排序、分页、权限、状态、幂等、副作用不能只靠传输成功、`code/success`、非空或 schema。

对象/数组根响应的稳定 JSON 片段默认用 `ass_json_all`：

- 每场景一份，汇集权威契约固定值/类型字段，优先于同字段多条等值 JSONPath。
- 对象递归部分匹配，额外字段忽略；配置字段必须存在且值/类型正确，不是整响应相等。
- 禁止空 `{}`、`[]`，执行器会跳过，不能证明任何事。
- 数组内容/数量严格、忽略顺序，不是部分成员匹配；仅集合、数量、配置字段稳定才放入。动态分页、变长或部分有序集合用 JSONPath/schema/针对断言。
- 生成 ID、时间、trace、token、随机、环境值及缓存比较等动态字段不放，除非权威预期确为固定；用 JSONPath/缓存/提取/schema。
- 已在 `ass_json_all` 覆盖的字段不重复写 `ass_jsonpath`；后者只加动态比较、特殊运算、null/空、集合及一致性无法表达的业务检查。
- 标量 JSON 或纯文本不用 `ass_json_all`，按响应和判定选文本、正则、缓存、JSONPath、通用或 schema。

### 6. 回读与覆盖对比

回读完整编辑态，对照清单/修复基线：

- 每个确认场景、请求分支、断言、前置及清理均准确存在；
- 描述明确普通语言测试点，不空、不只编号、不泛述、不依赖源码理解；
- 修复扩展删除 Case/步骤/场景为0，停用/解绑为0；
- 顺序与创建清单一致，修复仅有证据才改且保留其余顺序；
- 请求/业务断言未收窄，数据和清理完整；
- 逐场景审查非空 `front_func/posterior_func`：无通用模板复制和可替代的简单逻辑；保留项均有能力缺口、最小职责及替代评估，常规断言可在原生配置回读。未满足先整改，不以执行通过代替合规，不称编写完成或提交预发布；历史脚本逐项迁移并完整复验。
- 所有 SQL 已通过性能与数据库负载门禁，最终语句、实测耗时、资格条件及调用次数已核验；
- 消费工厂的写场景显式保存 API 新行清理/恢复，精确本轮标识，先于工厂清理；
- 标签精确匹配最终完整树重审，至少一项，无无依据/不支持标签。

缺失/收窄先恢复再执行，不能将缩减树当修复。

### 7. 完整编辑态验证

选可访问且安全支持整体的环境，必要时切换。写、工厂、SQL、夹具、破坏性操作和清理优先非生产。用 MCP 明确的 editing selector 调 `run_api_case`，不为执行而发布；单步骤调试仅排障，不作完成门禁。

验证环境不赋予/剥夺标签资格；执行后回读标签核对真实复用范围。测试通过不证明适合生产，不适合生产不证明非生产 Case 应延期。

读取最终结果检查全部场景、断言、提取、缓存、副作用及清理。非生产工厂执行核验执行级/项级清理及受支持残留检查；API 后代/关联与工厂全部项两类残留都为0，工厂清理成功本身不够。失败回诊断，不删失败场景、不弱化断言。

### 8. 版本与发布硬边界

**API Info 直接发布：** 在已授权创建/修复范围内，先自检接口 ID、method、URL/变量、协议、body type、参数、变更差异和引用影响，并按接口调试规则验证；只发布当前已验证的精确修订，回读 Revision/Release。不需用户二次确认，不套用 Case 的预发布/审批流程。已发布且内容未变则复用，不反复生成修订或发布。API Info 发布不会自动升级已有 Case 的固定版本，需在授权范围内明确重绑并完整验证 Case；无发布权限保留已验证修订并继续其他工作。

确认的独立创建、修复、扩展授权编辑态、验证及合格 Case 提交预发布，不授权 AI 正式发布，负责人也一样；定时报告修复同样遵守。预发布不二次确认。不每改一次就建中间修订或发布以获得可执行版本。

最终编辑态通过后内部自检：

- 类型、ID、名称和当前发布 Revision/Release；
- 方法、URL/路径变量、协议/体类型、步骤绑定、场景、断言、数据/清理等精确差异；
- 逐写场景清理矩阵：消费工厂键、API 新行、捕获标识、保存的 Case 后置、依赖顺序及零残留；
- SQL 的访问范围/索引或执行计划依据、实测耗时与结果、超时预算及累计调用负载；有 SQL 但未通过性能门禁不得提交；
- 全标签 `适用/不适用` 及依据，已保存 `scenario_tags` 精确回读；
- 适用的 Info HTTP-200 执行 ID/结果，或 Case 运行变量暂缓理由；Case 完整编辑态 ID/结果；
- 引用影响、旧发布及固定版本是否不变；
- 将生成和提交的 Info/Case 候选修订。

对冻结清单与权威契约，所有项正确、完整执行通过、覆盖/清理完整、标签对应候选且影响不超方案才可提交。记录自检，状态变更后向用户简报。候选变化则自检失效，重新验证审核。

合格 Case 无需用户二次确认：

1. 再比较覆盖，从通过的精确编辑态建且只建一个不可变修订。
2. 调 `update_api_case_publication_status(target_status="prepublished", revision_id=...)`，回读同修订为 `预发布`。
3. 无论负责人/正式权限均止于此；包括定时报告修复在内，禁止调 `update_api_case_publication_status(target_status="published")` 或通过其他方式代用户正式发布。
4. 加入负责人待发布交接清单，继续其余授权 Case。查询负责人只是可选交接信息，不是编写/验证/预发布前提。

发布权限是单资产交接边界，不是批量中断点。建修订/预发布也被拒时，保留已验证草稿和已有修订，记录具体拒绝和实际状态，加入清单继续其他授权工作。无法确认正式权限就不猜、不尝试，只将该转换待交接。禁止反复重试权限拒绝、绕过权限或声称草稿/预发布已正式发布。验证、清理、安全或编辑/执行权限不足仍是独立门禁，不伪装为仅待发布。

范围完成时汇总待用户审核发布的 Case，以及确因权限不足而未发布的前置 Info：产品/模块、ID/名称、已有修订、实际状态、完整执行证据、待发布动作、平台查明的负责人（未知就说明未解析）。告知 `请联系对应产品负责人完成待发布项的发布。` 不等待负责人后再编独立 Case。API Info 已验证且有权限时应直接发布并回读，再核对并按授权重绑 Case 的固定版本，不等待用户审批；确无发布权限且无编辑态绑定能力时，保存工作并记录依赖及发布后的绑定/重验动作，继续独立项，不造绑定、不称完整通过。

只有冻结范围外重大变更才再问。定时报告修复须额外给出跨批次去重的可复制 Case ID 行：只含真实 ID，以英文逗号连接、无空格，例如 `1,3,222,12`；请用户到页面查询并手动发布。用户确认后，由报告 Skill 回读精确发布 Revision/Release，核实对应已验证候选后精确重试，不能代用户发布。等待期间继续其他独立修复。

本 Skill 自己不重试报告行，由 `mango-scheduled-api-report-maintainer` 负责。

### 9. 来源记录回填

用户用例记录生成 API Case 后，按上下文确定源与可写字段。可以是飞书文档/表、Excel、MCP 用例库或其他结构化系统，沿用原写机制/字段，不限定文档类型，不新增不存在追踪字段。

Case 已创建并完整执行后，对每个匹配来源：

- 按字段含义和上下文而非固定名称匹配；链接如 `自动化脚本链接`、`自动化链接`、`API自动化链接`，ID 如 `自动化ID`、`API自动化ID`、`API Case ID`。
- 已有链接/脚本引用字段填真实 ID 链接 `https://example.com/#/apitest/case/details?id=<API_CASE_ID>`。
- 标识字段填真实 API Case ID；两类都有就都填。
- 结果字段同步完整执行结果：`通过`、`失败`，无法完成为 `阻塞`；不能由 Info 调试、部分步骤或未完整执行推断。
- 失败/阻塞在已有 `备注/探索性记录` 或等义字段追加场景与具体原因，保留无关旧备注。

不回填计划 ID、Info ID 或猜映射。支持时回读核验，不匹配、无可写字段或写失败如实报告，不冒称成功。

## 完成汇报

原用户已要求代码驱动完整模块/范围时，代表验证只是进度检查点，不再要下方续批选择；汇报后继续授权范围。仅代表/有限范围请求必须尊重，就绪默认不扩围。

新多场景来源完成验证首1–2个代表后，剩余前先暂停，汇报新建/复用、配置、覆盖、结果、清理和外部回填供用户查看，再要求编号选择：

1. **完成全部剩余：** 将验证模式应用完整剩余确认范围，执行、检查、回填。
2. **继续小批：** 再选1–3个代表或高优先级 Case，完成后暂停查看。

明确选1或明确全量/批量才扩至全部。只说继续默认2；有指定 ID 优先，否则按优先级/风险。代表 Case 修改要求先处理再扩围。

逐 Case 报告：模式、ID/名称、产品/模块、环境和标签；每个保存标签审核结论/依据；创建契约与场景或修复根因/证据；Info/步骤/场景/断言/数据/清理精确变更；编辑态 ID/时间/状态；覆盖前后及删除/停用/解绑数；Info 修订/Release；Case 修订、预发布结果与实际状态（普通流程待负责人正式发布，报告修复另记已核验 Release）；未解决项与安全恢复点；跨全部批次待负责人发布清单。不因发布权限停其余编写，不将待发布说成已发布。

仅完整编辑态通过且保留来源/已有覆盖才能说 `已创建完成` 或 `已修复`。仅保存配置应说 `已创建/已修改，验证未通过或未完成` 并解释。
