# 直接执行台账

真实项目实施/继续/完成/执行API自动化必须有唯一可写事实台账，优先平台服务自动化模块Case台账，平台工具不可用或用户指定才用外部。

## 支持载体

两阶段沿用入口 Skill：①模块接口清单生效按 `inventory_completed` 验收；②每接口完成图/场景、获准的自动化验证和覆盖回读后再做下一个。`scan_completed` 保留旧完整链路含义；待发布不阻后续接口，也不提前算覆盖完成。

每次启动或恢复按入口 Skill“每次进入先核查并告知项目进度”执行，沿用其进度展示、提醒、连续处理及用户停止规则；已完成部分复用，查询不自动授权写入或扩围。缺清单时核实接口归属，再按模块盘点完整接口清单。保留模块不代表必须同时完成链路；下面带 Mermaid/Case 的完整扫描规则属于后续分析阶段。若当前部署不支持模块纯清单，报告能力缺口，不改用无模块上传，不伪造图、Case、模块或“上传已生效”。首阶段清单不是可实施 Case 的执行台账，也不证明已完成自动化。

纯清单复用同一组工具，使用 `scope_type=module`、真实 `module_id`、`inventory_only=true`、Case 数为零；仅链路可缺省。含子模块时按已声明范围逐接口保留真实子模块归属。续传、分页接收对账、校验及 completed 生效沿用现有流程；回读 `summary.applied/inventory_only` 并核对模块。盘点不能用空字段覆盖历史链路、重置场景、移除未上传项或冒充完整链路扫描。完整分析使用 `inventory_only=false`，仍执行原门禁；两类基线分开核对。项目接口总量汇总全部约定模块后按稳定身份去重，不能简单相加复用接口。旧无模块记录保留历史，不作为默认上传方式。

上传判重与续传必须执行入口 Skill 的“上传前必须校验是否已有完整接口清单”：按精确产品、仓库/服务集合、分支、完整提交 SHA 及扫描范围核对平台基线；同版本完整生效清单回读一致则复用，版本变化按受支持的增量/全量协议更新，中断则按平台已接收稳定键续传缺项。只有本地路由集合与平台接收集合、预期/实际数量及生效状态全部核对通过，才能记“全部上传”。保留真实基线/上传 ID 和恢复点，不自创平台字段；接口列表查询失败不能当作首次上传依据，历史模块扫描不能证明项目级清单完整，也不得重置已有 Case 绑定和完成进度。

- `/mcp/api` 创建读取的模块扫描/Case，绑定精确产品、模块范围、仓库、分支、Commit。
- 已有Excel：表格Skill，保无关工作表/公式/样式/验证/已审核行。
- 飞书Docx/Wiki：解析节点用lark-doc；Sheet用lark-sheets，保无关tab行验证格式。

目录、Markdown/CSV/JSON、对话、无结构平台页不满足门禁，先验读写权限，每逻辑写批回读。

页面调用范围遵循入口 Skill：有前端项目已核实无页面调用的接口仍上传真实接口扫描，不创建真实 ApiCase；在现有接口说明/台账备注或交接清单记录 `无页面调用`、核查证据和页面接入后的恢复条件。MCP 没有接口说明字段时不擅传字段，也不把范围排除伪装成链路 Gap；通过已有可写说明载体记录并回读。没有前端的项目不显示此分类或空占位；源码/映射未取得只能写“页面调用关系未确认”。

已有且真实的未绑定场景行因无页面调用暂不实施时，保持实际测试归属，使用 `deferred/not_applicable`，在 `payload.remark` 写原因及重新启用条件；不进入有效目标场景实现率分母，但仍计入页面饼图的暂不处理数量，不算已完成。没有实际场景则只上传接口，不造占位 Case 凑说明。已有绑定及历史不得静默清空或降级，单独交接；前端调用状态变化须重新核查，不能只看后端 diff。该范围过滤不减少后端已发现接口数，零 Case 不代表自动化已全覆盖。

平台模式每接口每扫描不可变快照，每独立场景一个当前Case加不可变快照。`batch_upsert_module_coverage_interfaces`一次上传完整Mermaid及稳定节点/边，Case只含interface_source_key/covered_node_ids/covered_branch_ids，不自带Mermaid。整数schema_version3、准确预期数量，续传查双接收键，hash平台算。仅扫描可不绑定；真实自动化只用API资产流真实Case/修订。数量身份拓扑路径链质量全过才完成，计数标记验证不够；回读图及各路径。重扫同范围稳定键，语义未变保completed绑定；全量可移除缺项，增量只增改。扫描产物字符串"3.0"与平台契约独立。

## 受控字段与工作范围

下方表规则只用于Sheet/Excel；平台使用typed schema/enums。无内嵌Sheet的Doc/Wiki用相同选项受控文本，记录 `下拉不适用（文档载体）`，不称已设。用户必须交互下拉则停并要Sheet/Excel，不静默降级。

### 固定字段位置

来源证据在测试控制组前，代码证据/扫描基线提交是依据分类后紧邻独立自由文本：

```text
... | 依据分类 | 代码证据 | 扫描基线提交 | 测试场景 | 核心断言 | ... | 测试归属 | ...
```

代码证据仅仓库相对文件、模块类函数方法行号、直接相关测试定位，不放平台各种ID、运行史/报错、清理、诊断恢复。

扫描基线提交为产生该行的不可变源码，完整40位SHA；仓库不明时 `repository-id@full-sha`，仅真跨仓库链用分号多值。工作树干净或直读已提交树，不用脏HEAD/分支/tag/短SHA/时间/平台修订/猜部署版本。

测试场景和核心断言相邻分开。前者必填普通语言条件前置动作，无需ID/源码/参数/图/断言解码；标识输入约束只补充，不空/仅编号/实现/正常异常参数校验分支覆盖泛词，不限句式。后者精确可证伪外部判定：HTTP业务码关键字段、目标对照包含/顺序、状态、副作用、幂等、错误传播；不写结果正确、只成功非空。旧混合列只在证据足时拆，否则Gap不编。

8列控制输出组必须连续：

```text
... | 测试归属 | 测试层级 | 验证类型 | 执行场景 | 当前状态 | 自动化CaseID | 执行结果 | 备注 | ...
```

归属/层级/验证类型/当前状态单选，执行场景多选。数据策略/清理策略/代码证据/执行ID等不插组内，默认放组前，除权威用户schema另定。

已有同义列移动不重复造列，保每值公式样式宽度下拉颜色验证及无关列，移后回读管理范围/验证范围。不能安全移动则保旧布局、记精确位置Gap，不称规范完成。

不新建/保留自动化判定、是否需要完成（用户标记）、需要完成等选择列，当前状态唯一依据。旧列先映射回读全行不损样式验证再移除。Doc/Wiki保持同逻辑顺序。

CaseID/结果/备注独立，复用移动明确同义列，拆旧平台CaseID/执行结果，Gap/备注改备注并保值，不造重复。代码证据/备注不混列；迁移时建/移代码列到依据后、备注到结果后；定位入代码；仅当前未完成原因启用条件或当前失败恢复入备注；详细历史、非Case平台ID、时间、已解决诊断和成功清理回读入已有执行日志，无日志依赖平台不复制；保格式/验证并回读确认旧混合头消失。

### 原生下拉

有限可复用集合必须原生单选/验证，不仅文本约定；仅权威schema明确才多选：

- 存在时方法、版本、纯依据分类、归属、状态、布尔决策至少设下拉。
- 依据分类仅 `功能用例已核验`、`设计已核验`、`代码现状回归候选`，不加Gap/集成；未决暂不处理、备注原因。
- 归属仅 `HTTP API自动化`、`单元测试`、`集成测试`，无Gap。
- 层级仅接口/组件层、Integration集成、E2E端到端；服务自有DB仍组件，真实协作集成，完整业务E2E。
- 验证类型仅正常/异常/边界/权限/数据/流程场景，选主目标，不为加类型重复Case。
- 执行场景必填原生多选，本代码扫描流程只允许回归测试、发布验证、冒烟验证、数据校验、生产巡检、生产回归；临时验证、性能测试、效果评测、稳定性监测均禁选。每 Case 至少选一项有据适用的允许标签，不默认全选或全模块套用。逐项审核六类允许标签，四类禁选标签注明“本 Skill 禁选”，限制随交接传递，保存和绑定前回读校验。按副作用、数据隔离和清理判断，不凭当前环境或静态代码推定生产资格；生产巡检含 PUT/PATCH/DELETE、SQL/工厂、数据库或业务写入时无效，POST 需只读证据；生产回归含 SQL、生产连接或工厂时无效。评估可用环境后仍无适用标签，停止该 Case 上传，不留空或猜填。已有共享台账的其他流程选项及历史值不擅自删除，但本流程不得选用或原样交付禁选标签。
- 当前状态仅待创建/已完成/暂不处理；真实ID才完成，合格未绑定待创建，延期暂不处理，旧Gap迁暂不处理。
- 执行结果仅未创建/未执行、已创建/未执行、执行通过、执行失败、部分通过、不适用。
- Sheet原生下拉、Excel列表验证，覆盖完整管理行及已知有界预留追加行。
- 选项来自schema/权威流程/已验集合，保有效旧值；不编、静默归一未知、把错字变选项。越界旧值保留记Gap，冲突未解不建替换该列验证，冻结列及依赖默认分类平台动作，独立分析可继续，受影响Case不建跑。
- 新台账精确分类，归属与Gap状态分离，当前状态生成工作清单；版本保v1/v2/v3。
- 代码、定位、断言、请求差异、原因诊断备注自由文本，代码与操作诊断分列；混合受控标签和证据尽量拆，不支持则不强下拉。
- 除权威schema替换外保选项颜色值及无关格式。

设置后回读每验证范围，首末行选项正确、验证格数与范围一致，末行不能漏；分页截断取尽。连接器不能返验证元数据/全范围，记Gap，在平台执行前停台账修改，不称下拉完成。

### 当前状态决定范围

精确规范状态唯一工作信号：

- 待创建/pending_create：进实施清单和已登记目标，无ApiCaseID。
- 已完成/completed：须真实ID；计入有效完成数仍须通过平台当前有效性评估，不代表接口已分析或模块完成。
- 暂不处理/deferred：排实施清单与有效目标分母，保留在页面饼图总数中，留原因启用条件，无当前ID。

“暂不处理”的原因统一参照入口 Skill 六类说明，写入现有备注，不新增枚举。必须分开统计待分析/待取证与已确认暂不编写；平台三态暂存的未决项不代表已核实排除，不得据其不进入 Case 分母就宣称项目接口已分析完成。尚未开始分析的接口保留在接口清单，不为记录进度编造场景。每次更新或交接检查原因、证据、下一步和恢复条件；原场景可安全完成而只是前置/模型/清理待实施时，保持待创建，不改为缺能力。

结果只放执行结果，已完成仅绑定非通过。不按结果/旧选择/子串推范围，算指标前完整回读状态和ID。此规则不证明可执行，也不绕API Skill的数据授权清理环境去重门禁。环境本身不使deferred，测试可安全运行则pending非生产标签切环境；只有评完后有据权威/自动化/归属/平台缺口才deferred。

### 单元职责

精确归属单元的行，文档显示非自动化职责，表仍规范单元值，备注写HTTP不可达，仅有歧义再加非职责；状态暂不处理、结果不适用，无平台探索ID留空；记源码/隔离行为/建议位置/已知负责人，不建改跑或称单测完成；排API数量分母通过率，单元数单报。

历史探索Case已证HTTP不可达则保历史ID/失败在平台史或历史证据字段，不删；当前覆盖绑定空、标单元、历史执行不算API，不为自动化重跑。

### 平台能力延期

行为预期已知但平台无法确定构造/观测（超时失败、固定未知响应、第二租户、预期401、时钟、runner等）记测试平台能力Gap。

用户/策略延期时保独立归属，缺Stub/身份/时钟/runner不改HTTP为集成；状态暂不处理、当前ID空、结果不适用，历史探索只留历史；简记能力/不完成决定/启用条件，排工作/完成/通过分母，不擅建能力。不是已通过或分支消失，能力变化后重评。

### 绑定与结果回填

- 自动化CaseID自由文本，真实平台返回/回读前空，不填占位、Info/步骤/场景/执行ID/状态。通常一行一ID，故意多Case才逗号并备注映射。
- 结果完整管理范围原生单选六项。创建复用回读后已创建/未执行；查最新单Case事实后通过/失败/部分。故意非API才不适用；创建失败无ID仍待创建、未创建/未执行，备注失败。
- 代码证据在依据后，仅源码/测试定位，新版本链变化更新，不贴平台日志；基线在其后，仅明确仓库清洁/已提交源后写，不因有新commit就覆盖。
- 备注是简短当前结论非追加日志。暂不处理写具体原因/必要启用；失败/部分写当前根因恢复条件（含未决清理残留）；已验证通过通常清空已解决史，除重大未决风险。常规Case/Info/Revision/Step/Scenario/Execution ID、时间、创建过程、成功断言清理回读、已解暂态不写。
- 详细尝试诊断重跑清理在平台/最终结论/用户另要执行日志。用工厂时最终仍说明清理是否验证，成功行备注空不等不验清理。

每重要里程碑立即回填回读，不等最终；回读匹配才称同步。写读失败不称完成，保精确待回填。请求身份前置数据SQL工厂副作用断言清理调度变化使标签审核失效，上传交接绑定完成前重新审核六项允许标签、核对四项禁选并回读，审核仅绑定精确快照/修订。

## 工作表布局

Sheet/Excel默认恰两业务表：基础统计、Case明细。用户未要求不另保接口与平台现状、接口与代码链路、Gap、执行日志表/段。旧三段简化先确认原来源行动在Case或平台保留后删重复汇总。无内嵌表Doc/Wiki用同逻辑两标题。

### 基础统计

紧凑展示产品、范围/基线、查询时间及入口 Skill“页面与 MCP 统一统计口径”的①②③④指标。平台数据优先使用 `get_module_coverage_metrics.overview`，不以绑定行数或顶层旧指标替代有效完成数；③分别标明“页面已完成占比（含暂不处理）”与可选的“已登记有效目标场景实现率（不含暂不处理）”，禁止简称模块完成率。零分母显示 `—`，缺数据写“未核实”。另列接口绑定、执行结果、暂缓原因及待发布/待绑定事项；代码基线表按组件/仓库/Git提交/扫描范围展示。纯外部台账无法提供平台分析/有效性数据时明确缺项，不从场景状态反推接口分析完成或模块验收。

六列A:B/C:D/E:F每行最多三对指标，首行可标题状态组件数时间，不加类别行或每指标一行。不可达延期原因适用保留；数整数、率百分比。代码扫描基线标题后四列表，仓库/组件一行，完整40SHA，范围真实目录文件层。

统计面向决策，不重复方法URL/唯一路径指标，除用户对账。归属合计对总Case、原因对暂不处理且用当前原因。默认不加工厂Case、清理成功、残留指标，证据留平台/最终，用户要才加。

仓库时效按下文依赖diff，身份commit明确且干净/扫描提交树才基线匹配；待重扫数来自受影响接口集合，不只文件名。业务时区 `YYYY-MM-DD HH:mm:ss`，完整/增量扫描及相关表写回读全成功才推进统计时间；失败部分、仅样式、仅执行不推进。不放逐接口URL、Info/修订、ID列表、链、运行史、清理长文，不把暂不处理叫Gap；单元和能力延期排完成通过分母。

### Case明细

独立可控可观察场景一行，标准序含稳定CaseID、模块层级、接口名/方法URL/标题；依据/代码证据/基线；场景/独立核心断言、分支ID、前置数据、数据/清理策略；归属层级验证标签状态CaseID结果简备注。接口链事实只在这些字段，不另重复接口汇总。

### 增量重扫

逐仓库解目标完整SHA，对行基线取提交diff文件/符号，沿链和共享路由授权schema异常事务扩影响，直接/传递接口全追。行号移动不等语义，接口文件未改不证明共享依赖无影响。

受影响更新证据/职责/CaseGap/执行需求，扫描回读成功才推基线；未影响需完整依赖diff证明才推。仓库身份、祖先、工作树、影响、扫描、回读未解保旧基线记阻塞。部署commit如有单独存，不当源码基线。版本前缀后路径同不合v1/v2/v3，非自动化/配置权限租户模型灰度排除及启用条件在对应Case，不静默漏。

语义身份重扫：新接口场景新稳定键、pending/deferred；触发/前置/结果/副作用/方法路径版本改变即新身份，审核全量可归档旧覆盖，不自动转旧绑定，须下游证等价；仅模块/归属/层级标签/状态/图选择/标题断言文字/证据基线改保键，语义不变保completed真实绑定，需改ApiCase先API Skill，不因分类重复建；增量未出现不变；完整已证全量缺项经缩范围审核标removed，不删绑定Case；移除身份重现复用键，只有下游验证回读才恢复绑定。

增量 `base_commit_sha` 必等同产品根模块仓库分支include_descendants范围最新completed的精确commit_sha，否则全量或先补历史。全量有意范围缩超半，先核全移除集再用confirm_scope_reduction=true。详细执行事件默认在平台，仅用户要求才另文，不默认日志表。

## 更新协议

平台模式先分页查全指定范围的扫描、接口和 Case，使用准确的预期数量及整数 `schema_version=3` 创建扫描，续传时核对两类已接收键。先上传接口，再上传 Case；不提交 `automation_decision` 或 `case_no`。内部链路未解析的接口必须提供 `gap_reason`、`next_action` 和 `resumption_point`。

仅维护扫描台账时，新建且未绑定的 Case 使用 `pending_create` 或 `deferred`；已有绑定且语义未变的 Case，重扫必须保留 `completed`、`api_case_id` 和对应修订，不得静默清空或降级。同一次上传中的同一 `source_key` 不得从未绑定改为已绑定；扫描结束后，如需实施自动化，先创建或复用真实 ApiCase、回读 ID，再调用 `update_module_coverage_case_binding`，由平台自动改为 `completed`。

仅 `valid=true` 时才能以 `completed` 完成扫描；仅 `valid_with_gaps=true` 时才能使用 `completed_with_gaps`，后者只是审计终态，不生效快照。随后通过 MCP 回读扫描、接口、Case、快照、高亮流程、差异和指标，确认接口 Mermaid 及每个 Case 的节点/分支 ID 与提交值完全一致；当且仅当存在当前 ApiCase 绑定时才为 `completed`。

全量核对须包含已移除 Case，归档必须先审核，不得通过模块台账删除已绑定 ApiCase。运行时覆盖报告另行保存；`uploading`、`cancelled` 和 `completed_with_gaps` 扫描均不得作为当前生效扫描。

外部台账：

1. 扫前写读范围。
2. 发现接口先登记再设计Case。
3. 逐接口更新链与权威对照。
4. 每业务分支唯一归属/责任。
5. 实现补充分支先代码候选，权威审后升级。
6. 不完整冲突记Gap不猜。
7. 编ID/建前去重。
8. 真ID回读后立即回填，结果已创建/未执行。
9. 重要尝试留平台或另要日志，最新核实结果与当前失败原因覆盖备注，通过清旧除未决风险。
10. 硬停记已做、阻塞、范围、恢复点。
11. 每修改范围回读，没读成功未完。
12. 新值前给受控字段设/扩原生验证。
13. 可行确定后当前状态规则，回读完整状态/ID范围。
14. 全标签重审并回读多选，无审/过时/空/不一致阻上传交接绑定。
15. 场景空、编号、泛述、实现或普通测试不理解阻扫描完成/交接/绑定/完成。

不依赖聊天史，用户也应从台账理解接口、权威预期、代码路径、场景、当前状态、平台资产、结果、诊断、清理和未决Gap。
