# 执行与验收

真实执行、清理、失败清理修复及最终汇报前读取。

## 配置验证（不写业务）

顺序：变更新字段 `preview_data_factory_field_values` → 直接/内部再递归父模板 `preview_data_factory_template` → 每绑定 `preview_data_factory_case_config` → `update_data_factory_entity(status=1)` 与 `set_data_factory_template_status(status=1)` 启用并回读status/config_status。

必须 `can_debug_run=true`、missing_fields/all_missing_fields空、无依赖/回写错、必需输出非空。预览生成ID不是真DB生成ID。

## 真实执行门禁

只有用户授权真写DB才执行：

1. 用精确环境/上下文/覆盖 `preview_run_data_factory_template_impact`。
2. 核库表、根项载荷、依赖、输出、回写和can_execute；所有已确认数据库自动生成列均默认跳过且不出INSERT，不只检查自增ID，不能以显式null/空串代替省略。必需输出取插入后真实生成值。
3. 对用户授权范围；已含相同非生产完整创建修复验证则工具协议内用既有授权不重问，否则先展示影响取得确认。
4. `execute_data_factory_template` 输入不变，加精确预览token及确认文本。
5. 记execution_id/编号/来源/库/生成主键/输出/cache_keys。

不为启用而真实执行；纯配置请求通常预览通过即可完成。

真实执行前同时核对入口 Skill 的业务隔离门禁及场景建模证据：最终载荷没有共享业务身份冲突，复用对象资格正确且不在清理集合，消费步骤使用本轮统一输出。字段预览通过或 can_execute 为真，不代表平台已经自动检查业务隔离。

## 清理

工厂行按执行记录中的精确 SQL 主键清理；关联 ES 仅按执行时已冻结的资源快照验证/清理，不自动发现或接管其他资源。

若资源由被测 API 创建，而非工厂 INSERT，则改读 [API 创建资源的编写与清理](../../mango-api-case-builder/references/api-created-resource-cleanup.md)，使用 Case `resource_cleanup` 及其台账；本节模板 `cleanup_resources` 的插入前 ES 基线与字段映射不能直接套用到 API 响应后的资源登记。

- cleanup_order小先，子关联先父根，不并发清依赖。
- 执行结束清理在请求/提取/断言/后续失败也运行，缺清理记录按路径配置问题查。
- 手动重试前 `preview_cleanup_data_factory_execution_impact`，核执行项、库、主键、顺序、跳过项。原授权非生产本轮精确行无需打断；扩围/归属未知需确认。然后 `cleanup_data_factory_execution` 带token/文本。
- 已无行按现平台幂等，不扩删除条件，不删非本轮。
- API别表引用导致失败先修Case显式后置，不自动发现递归删未知表。

同非生产源只读主/业务键限定SQL核每项零残留，平台状态本身非残留证明。API新行单独验，先API后代再工厂子根，遵全部外键业务引用。

### 关联 ES 清理

适用于 SQL 行同步为单个 ES 文档，且文档 ID 来自该行稳定唯一字段的场景。先核对实际同步代码的索引、文档 ID、租户路径及环境 ES 绑定，不按表名猜映射。只读核验使用另行授权的专用工具；不得通过测试平台 MCP 提交 SQL 或通用脚本绕过查询限制。

通过现有 `create_data_factory_template` / `update_data_factory_template` 的 `cleanup_resources` 保存完整规则列表，最多 5 条。例如：

```json
[
  {
    "datasource_alias_id": 8,
    "index_template": "example_template_{tenant}",
    "document_id_field": "id",
    "tenant_field": "tenant_id",
    "tenant_path": "tenant_id",
    "mode": "verify",
    "timeout_seconds": 15,
    "poll_seconds": 1
  }
]
```

示例数据源 ID 必须换为同产品的实际 ES 逻辑数据源。规则遵守以下边界：

- `document_id_field` 不传/null 才使用 SQL 主键；显式指定后必须是实体实际落库字段，缺值直接失败，不回退。例：落库 `{ "_id": 41, "id": 1001, "tenant_id": 7 }` 时，SQL 按 `_id=41` 清理，ES 按文档 ID `1001` 检查，不能查文档 `41` 后宣称成功。字段值、租户和映射在生命周期内须稳定，不能传固定文档 ID、拼接表达式或外部计算值。
- `index_template` 是精确索引，仅允许一个末尾 `{tenant}`；不使用通配符、多索引、任意 DSL 或别名重定向。`tenant_field` 来自 SQL 行，`tenant_path` 来自 ES `_source`。
- 默认 `mode=verify` 只等待并回查业务同步删除；只有明确获准补偿删除时使用 `delete_and_verify`，不能为让验收通过静默升级删除模式。观察窗口 2–60 秒，轮询 1–5 秒；生产禁写边界不变。
- 执行时 SQL 提交前须证明精确 ES 文档不存在，平台冻结 SQL 主键、ES 文档 ID/来源字段、租户、环境、绑定及连接版本。已有文档或基线查询失败会拒绝接管并回滚本次 SQL；不得关闭规则绕过。根、子表及依赖模板各自配置和核验自己的资源，不能只配根模板就称全链覆盖。
- 清理先完成 SQL，再观察完整窗口，末尾连续两次无文档才成功；条件删除校验文档归属和版本。索引不存在、权限/连接异常不等于文档已删除。SQL 已清、ES 失败时保留失败及待办，受控重试只处理快照资源，不重新造数。
- 历史执行无快照时，新规则不会追溯接管；旧主键映射快照不会随模板改变。不得手工补快照、改记录或把历史文档加入新执行；另行核对租户、真实业务记录和精确文档并取得处理授权，不能宣称新配置已清理历史残留。

调用前核对实际 `tools/list` 中两个模板工具的 `cleanup_resources` 和内层 `document_id_field`。仅 `get_data_factory_schema` 有文字说明不代表工具支持；缺参时先刷新/重连客户端，再由平台维护者核对对应 MCP 入口及全部进程部署版本。仍不支持则停止该配置，不改用直接 HTTP、平台数据库或临时 Case 绕过。

验收记录每项 SQL 清理结果、关联资源快照和 ES 检查/删除结果，并用获准专用工具独立精确回查。统一数据源审计仅是执行证据，不代表所有副作用已覆盖；多文档、Redis、文件等仍需独立失败安全清理方案，不能沿用此规则冒称支持。

### 生命周期与隔离验收

- 核对创建、复用和清理归属：清理集合只能包含本轮创建且获准删除的精确对象，不包含只读复用的预置/共享行；本轮所有同步消费者和实际异步任务须已完成或按失败路径安全收敛，不能在步骤仍需使用前清理。并发 Case 不得依赖另一执行待清理的临时对象。
- 结合读取代码、冲突检查及必要的授权验证，确认本轮对象不会因共享业务键被无关消费者错误选中；有正常运行范围内的缓存/索引/异步副作用时，核对真实失效、删除及完成证据。数据库零残留不能单独证明未干扰业务，也不能因此擅自清共享缓存、删未知索引或扩展清理范围。
- 无需声称观测了所有无关请求；说明已查消费者、作用域、验证范围和未决证据。缺少隔离或清理依据时不能称安全完成；已发现污染或引用时，先保留证据并修正方案，不以取消清理或永久保留冲突数据掩盖问题。
- 建模/修复验收至少考虑三种反例：同读取作用域内保留业务身份相同但主键/名称不同，仍应阻止作为独立临时对象创建；合格只读复用的预置对象不得清理；两个执行的临时对象不能被彼此或共享读取误命中。可用代码与配置证据验证，不把反例检查当成真实写入或并发执行授权。

MCP发布Case前读全树，消费缓存的每写场景都须保存用本轮响应ID/唯一键定位全部API后代/关联的Case级后置。工厂状态、设计说明或响应后处理都不够，缺/不可证禁止发布。

## 清理失败待办

读待办、执行/每项、策略顺序状态、记录库表键、精确错；区分SQL/配置、源权限连接、依赖序、超时、缺行、部分清理；修底层实体/模板/Case，不反复重试未变失败；预览确认后重试，核执行/项结果及零残留；刷新待办验关闭，仅工具允许且独立清理证据齐才人工处理。

## 停止条件

以下任一不启用/执行：生产或环境绑定歧义；schema不可读/必要环境不一致；任一自增ID非零生成/覆盖；必需外键无已证行/合法值；预览缺值/类型错/依赖未解/非法回写/缺输出；将整表覆盖不完整items/output_config/post_insert_updates/字段；真执行清理缺预览或缺精确非生产任务授权/新确认；无法证明全项成功加零残留；消费写Case新关联无已保存精确失败安全后置。

共享业务身份冲突、读取隔离证据不足、复用对象被列入清理、消费者尚未结束或缓存/索引副作用无法安全收敛时，同样停止受影响的启用、绑定与真实执行；不扩大为对无关安全资产的全局停用。

## 最终证据

报告产品模块环境逻辑源；实体ID/表/schema对比；模板ID/用途/状态/config、依赖回写/预览；Case配置ID/来源类型/缓存变量/绑定预览；真执行ID/生成键/执行项状态/清理/零残留；待办ID和刷新后状态；API新关联单独清理；消费Case清理矩阵（工厂键、API新行、捕获ID、Case后置、顺序、零残留）。

无执行记录、任一项失败/非预期跳过或未验残留，不得称执行/清理成功。
