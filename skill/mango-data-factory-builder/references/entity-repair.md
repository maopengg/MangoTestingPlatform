# 实体修复与启用

创建/同步实体、修schema无效模型、模型待办或重新启用时读取。

## 发现真实目标

1. 确定获准产品/末级模块，查逻辑源及环境绑定；非生产连接/权限不明则测试检查。
2. 用表、逻辑源、产品、明确 `test_env` 调 `get_data_factory_table_schema`，先记真实列和主键再看旧规则。
3. 有代码就追建映射读写：已执行DDL/ORM、枚举常量、DTO/schema、mapper/repository、service条件状态、默认关联、测试调用方。按表/模型/mapper/列搜索，不止首文件；代码未表达语义才用维护文档，记修订/版本。
4. `get_data_factory_entity_detail` 读已有实体，停用则查 `status_change_reason`、来源、时间、引用及 `list_data_factory_entity_status_logs`，区别人为/监控/MCP/系统修复/同步。
5. 按entity_id查直接模板；同产品 `enabled_only=false` 分页取尽，递归找 `items[].child_template` 父模板，查受影响Case绑定。

## 新建

用 `create_data_factory_entity(sync_fields=true, test_env=..., status=0)` 保持停用草稿，语义审核预览完再启。空壳不可用。不以 `batch_generate_data_factory_entities(sync_fields=true)` 作为AI最终建模，因为可能先启未审规则；仅明确批量物理盘点可用，结果均临时，须逐个停用回读、审核修正预览启用才可用。

真实表名加清晰别名，当前 `create_type`/`delete_type` 是SQL（`2`）。`cleanup_order` 小者先，子/关联小于父。创建回读非空字段，修不符业务状态的建议；schema建议仅起点。

## 与代码一致的字段模型

最终保存前逐字段分类，留生成器依据；表多/建议可执行不降低标准。至少核：

- 物理类型/可空/主唯一/生成/默认/长度/索引外键；
- 数据库或业务枚举、布尔标记、合法值和标签；
- 租户、创建更新、组织、账号隔离；
- 外/业务键、资格、依赖实体模板及是否同执行输出；
- 状态、软删、有效期、迁移终态；
- JSON/list/object结构、必需成员与序列化；
- 类型状态模式导致的必填/禁止/解释变化；
- 是否必须省略以应用DB/应用默认。

生成器必须：

- 数据库真实自动生成字段默认 `generator_type=0`，包括自增、生成/计算列、数据库默认表达式和触发器维护值；INSERT 必须省略，不发送 null/空串，不用固定值或表达式代造。检查目标库实际 DDL/触发器，ORM 应用层生成不等于数据库会生成。普通业务 DEFAULT 依入口 Skill 区分生成归属与场景显式赋值，不把所有带默认值的枚举一律跳过。
- 租户/审计/组织/账号/操作人用已测上下文缓存/依赖；除契约定义确切字面量外，固定共享ID无效。
- 外键/业务引用有依赖或满足全部租户状态类型的权威存量，不随机或任取首行。
- 调用方唯一/业务键遵代码长度前缀字符大小写校验范围及防冲突，用无冲突表达式，格式允许才AUTO。
- 可选字段仅合法省略才跳；nullable不证明适合当前复用场景。

按入口 Skill 分开确认物理结构、运行行为和业务预期。已确认契约与运行行为有冲突时，先核对适用版本和场景，保留差异并暂停受影响的启用。

### 穷尽证据再问

依次读任务/确认上下文/附件示例描述；目标环境完整schema注释默认索引键关系；可用仓库附件的DDL/ORM、mapper、枚举、DTO校验、service、转换、测试调用；对齐各来源的适用范围。旧模板仅提供参考。证据仍不足或契约冲突影响合法数据及场景时，再提具体问题。

已有建表映射和使用代码能回答的直接解，不让用户重述；不以固定/随机/猜枚举/首行/假关系逃避分析。必须问时写字段关系、已查来源、选项差异并保持停用。

### 枚举硬审核

查所有注释与代码枚举常量，特别 `*_type`、`*_status`、`*_state`、`*_mode`、enabled/valid/删除标记。`1.Name A 2.Name B` 注释用于辅助解释，实际值核对运行代码及适用契约。遇到业务契约冲突按入口规则处理。

每已证枚举须有完整且保类型 `enum_values`、`generator_type=9`、同集合 `generator_config.values`、可读 `generator_config.options` 的 `{label, value}`、通常稳定 `generator_config.mode=fixed`、有业务依据的合法 `generator_config.value`。

禁止改成type1、随机数串或无标签值。特定状态用枚举fixed，差异在最窄模板/Case层覆盖但不丢集合；只有全部选项同配套要求及有效性才随机。

发现建议9无代码证明非有限域不降级；代码发现漏枚举手动补全。旧普通固定规则被代码证明枚举即无效，迁9，旧值仅合法适合才作默认。仅缺少注释或已证实注释过时时，可按已核实的值配置。影响场景的证据缺失、版本不匹配或契约冲突须先解决。

## 安全合并schema

不直接把真实 `columns` 传 `batch_save_data_factory_fields` 覆盖已有规则。按字段名完整合并：

- 当前列决定名称顺序、db_type/platform_type、可空、主键、自增、长度及有据枚举元数据。
- 未变字段保generator_type/config，结构或语义无效才迁（已证枚举用普通值、随机外键、违代码值均无效）。
- 新字段从建议起步再改合法业务值。
- 只有真实列不存在才移除；replace=true前列被删字段及模板输出绑定修复引用。
- 新非空且无默认/自增/生成列必须非空、类型正确、业务有效生成器，不用随机数满足外键或*_id。
- 所有覆盖遵数据库自动生成字段及主键不变量；旧固定/随机/枚举规则或模板/Case 覆盖不能使数据库生成列重新进入 INSERT，不能因“保留已有规则”保留此类错误。

`preview_data_factory_field_values(entity_id=..., test_env=...)` 预览完整列表，全部有效才 `batch_save_data_factory_fields(..., replace=true)`。再读实体/schema比完整签名，保存成功不证明一致。

## 生成方式

使用 `get_data_factory_schema`、`list_test_data_methods` 不背表达式：

| 类型 | 含义 | 用途 |
| - | - | - |
| 0 | 跳过 | 数据库自动生成/计算/触发器维护、由DB负责的默认值，或有意合法省略的字段；INSERT 不包含该列 |
| 1 | 固定值 | 权威非枚举常量，非上下文或DB/应用默认拥有 |
| 2 | 随机串 | 语义不重要的编码 |
| 3/4 | 随机整数/小数 | 已证合法范围 |
| 5/6 | 当前/相对时间 | 时间与有效期 |
| 7 | UUID | 调用方UUID/追踪键，非自增 |
| 9 | 枚举 | 有标签的有限业务域 |
| 11 | 依赖 | 其他实体/模板/节点产外业务键 |
| 13 | 数据表达式 | 名称邮箱电话编码缓存上下文 |

随机字符串格式允许必须大写AUTO（名字、标题、描述、编码、邮箱本地部分、自由文本），用 `AUTO${{...}}` 或等效前缀。非串、DB生成ID、枚举、严格UUID/电话/身份/签名/哈希/协议、精确查找键、权威常量可豁免，不能为方便去掉，保理由。随机不能使值非法或换分支。

枚举值和标签按运行事实与适用契约核实，`0(0)` 不完整。冲突按入口规则处理。固定一个默认仍type9，布尔有限含义也是枚举/标记。JSON、软删、租户、审计、状态复现真实代码，不仅匹配物理类型。

## 修复全部受影响模板

实体修复需模板绑定闭环：

1. 先直接模板再递归父，实体停用也可预览。
2. 修过时 `field_overrides`、`items[].field_overrides`、`output_config`、`post_insert_updates`，必填放实体默认/模板/父项/Case最窄可复用层。
3. items提交全部原项，回写/输出提交完整目标列表。
4. 每模板直到 `can_debug_run=true`、无缺字段、依赖已解、枚举配套合法、输出齐。
5. 每Case用保存覆盖预览。
6. schema/预览都过才 `update_data_factory_entity(status=1)`，看返回模板重验；未自动恢复的显式修启，不擅自覆盖有意手停。
7. 回读拟执行实体status1、模板status1/config_status1。

## 待办关闭

模型无效先保待办基线并修实体，`refresh_workbench_todos`再查待办详情，凭客观有效自动关闭，不人工掩盖schema/模板问题。

表缺/schema不可读、必要环境结构冲突、无代码/可靠后备定义必需值、代码枚举不完整矛盾、模板绑定不能预览、启用失败时停止报告。已证实过时的注释可记录并继续。已确认契约与运行行为冲突时，核对适用性并暂停受影响的启用。
