# 受限环境测试与本地证据验证

## 用途

发布验收的完整判定无法在 mango-test-platform 内完成时使用，典型情况：

- 平台可执行 API，但不能连接环境数据库；
- 目标环境禁止平台 SQL；
- 执行器不能访问 API，而获授权本地电脑可以；
- 最终判定须结合 API 与只读数据库/观测证据。

只负责跨边界验证，不替代 Case 创建、报告修复、环境配置或业务设计。需改 Case先完整读 [API Case Skill](../mango-api-case-builder/SKILL.md)；源自定时失败报告则读 [报告修复 Skill](../mango-scheduled-api-report-maintainer/SKILL.md)。本 Skill 只负责外部证据与综合结论。

## 不适用范围

禁止用来给受限 Case 加 SQL/连接/工厂/数据库清理；平台能安全完整执行时绕过平台；SQL 直接改业务数据；修余额、交易、任务、配置、权限、产品状态；功能不完整就弱断言；将某产品接口、表、ID、错误码或计费规则固化为通用规则。

## 必要上下文

执行前明确：

- 精确产品、Case ID 或已批准请求流、目标环境，环境属仿真/蓝/预发还是生产；
- 本地创建、修改、触发、通知、扣费等有状态调用的明确授权；
- 平台能力：API可达但SQL不可用，或两者都不可用；
- 权威请求顺序、断言、轮询终态、超时、清理/保留策略；
- 秘密引用和环境变量键，不在方案报告放原凭据；
- 本地只读数据库工具、逻辑实例/库、权威结果 schema 或发现办法；
- 观测工具、组织/stream/服务定位、日志保留窗口、关联字段；
- 请求/业务/任务/文件/trace ID 或本轮唯一标记等确定关联策略；
- API、DB、日志哪些事实共同构成通过、失败、跳过、阻塞或无法判定。

不猜同名环境、Case、库、namespace、deployment或表。用平台元数据、部署配置、权威代码文档、工具发现或一个精确问题消除歧义。

## 执行模式选择

执行前建能力矩阵：

| 模式 | API 执行 | 数据库验证 | 适用情况 |
| - | - | - | - |
| 平台 API + 本地证据 | mango-test-platform | 获授权本地只读工具 | 平台 API可达但不能执行所需SQL |
| 本地 API + 本地证据 | 获授权本地 HTTP/测试客户端 | 获授权本地只读工具 | 平台不可达或不得调用目标API |
| 仅本地证据 | 不发新API | 获授权本地只读数据库/日志 | 用户只查已完成执行 |

保留确认语义时优先平台。仅边界要求或用户明确指定才用本地 API。本地精确复现发布/确认契约的方法、URL、头、认证来源、body、文件、提取、轮询与严格断言，不为成功漏步骤、换身份/秘密来源、改字段或接受不同结果。

## 安全边界

### 测试平台

- 所有受限环境 SQL、连接、DB断言和清理留平台外。
- 本地凭据、连接串、token、Cookie、秘密不复制到Case、公共变量、报告、Markdown附件或仓库。
- 确认的判定含外部证据时，不能因平台/API部分通过就称全通过。
- 不加占位SQL、跳过SQL断言、`allow_failure`或弱断言伪装数据库能力。

### 本地数据库

- 仅任务相关 `SELECT`、元数据及受治理工具支持的只读 explain/内省。
- 禁止 `INSERT`、`UPDATE`、`DELETE`、`MERGE`、`REPLACE`、`TRUNCATE`、DDL、权限、可写过程、临时修数据和SQL清理。
- 按精确环境和本轮标识查询；有请求/业务/任务/基线 ID 时避免租户全量或仅时间条件。
- 确定排序、有限limit，不任取第一条当证据；缺行是调查线索，不授权造数修复。

### 本地 API

- 生产或其他实质有状态调用需明确目标和范围授权。
- 仅正常产品API，不用私有修复入口或临时绕过。
- 首写前生成唯一关联标记，在支持字段贯穿请求。
- 未证明幂等，不重试写请求；或用户明确授权带新标记的新执行。
- 最小安全对象/范围，避免真实用户通知、不可逆流程、外部收费和第三方影响，除其就是明确授权测试目标。
- 确认设计有可靠失败安全路径才用批准产品API清理，绝不SQL清理。无安全清理，创建前披露保留对象并取得授权。

### 证据与秘密

脱敏授权头、Cookie、应用秘密、数据库凭据、签名载荷、私钥和个人数据。关联ID可以报告，但本身是凭据/敏感租户用户属性的需遮盖。最小摘录足够时不贴完整日志。

## 验证流程

### 1. 平台基线

读完整已有 Case 和发布/确认请求流，记录：Case ID、名称、Release/Revision、环境、标签、负责人；步骤顺序、Info/版本、场景参数ID、头、提取、断言、轮询、清理；秘密/公共变量引用不暴露值；业务终态与外部数据判定；目标环境是否有禁SQL/连接/工厂。

需改 Case走API Skill方案、回读、执行、提交门禁；不能本地补救错误 Case后声称平台资产有效。

### 2. 冻结证据清单

执行前内存保存环境/模式、服务地址和身份来源、Case/修订或请求来源、唯一标记格式、API终态、持久结果与区别字段、库定位与只读键、日志定位/关联链、超时/重试/清理/保留策略、最终通过失败规则。环境、身份、语义、副作用、清理或判定变化时，影响动作前停下并展示差异。

### 3. 可选执行前基线

判定依赖增量而非绝对状态时，本地只读采最小基线：最新相关行ID、执行身份内计数、状态/版本、前余额/聚合、已有标记行。记数据源、时间、数量、基线键，不改数据制造干净基线。

### 4. 执行 API 部分

**平台 API + 本地证据：** 执行精确 Case/场景，轮询平台终态，读取请求响应、提取断言和轮询输出，捕获关联ID与执行窗口。

**本地 API + 本地证据：** 从批准秘密/配置源运行时解析 → 生本轮标记 → 按顺序复现 → 相同传输与业务断言 → 异步轮询至文档终态/超时 → 保存脱敏请求元数据、响应码、ID、时间。

任务创建不代表异步成功；超时仍是超时，无权威依据不无限延长或弱化终态断言。

### 5. 本地只读查持久结果

最小确定查询优先：精确请求/幂等ID → 本轮响应业务/任务/文件ID → 本轮标记加租户环境 → 精确身份加基线后ID → 有界时间仅补充，并发可能歧义时不能单独作身份。

核对权威主记录及必需子明细，按清单验证版本、金额、状态、有效性、归属、路由码、计数、关联等。字段从权威证据发现，不硬编码某产品schema。通用形状：

```sql
SELECT <authoritative_fields>
FROM <authoritative_schema>.<result_table>
WHERE <environment_or_tenant_scope>
  AND (
        request_id = :request_id
        OR business_id = :business_id
        OR unique_marker = :unique_marker
      )
  AND id > :optional_baseline_id
ORDER BY created_at DESC, id DESC
LIMIT :bounded_limit;
```

确认真实标识、列、索引、时间语义后才适配。

### 6. 缺失或不一致诊断

API成功但持久结果缺失/错误时不立即归咎数据库，也不判通过，依次：

1. 确认预期身份与唯一标记已带上；
2. 按请求ID查审计/网关；
3. 获取trace/log/span/下游请求ID；
4. 跨网关和目标服务追链；
5. 用观测工具要求的namespace/deployment/service精确过滤日志；
6. 定位下游持久化/上报被调用、跳过、拒绝、重试或失败的决策；
7. 取真实下游身份与脱敏业务参数；
8. 取下游响应码/消息/异常；
9. 适用时用新证明的ID重查DB。

至少区分：未调用、文档规则有意跳过、调用后落库前拒绝、落失败记录、成功记录在另一已证ID下、下游业务失败而API仍成功、权限/保留期/埋点/工具导致证据缺失。引用日志不露完整token/敏感载荷。

### 7. 综合结论

API结果与外部证据分开，再按冻结判定综合：

| 结论 | 规则 |
| - | - |
| Passed | API断言通过，异步到要求终态，全部外部数据断言通过 |
| Failed | 充分证据证明行为/持久结果违背权威判定 |
| Skipped | 确认场景有意不适用，或需已知不支持故障注入/依赖 |
| Blocked | 有效执行完成前缺必需授权、连接、配置、秘密、数据或能力 |
| Inconclusive | 已执行，但ID/证据不足以确定通过或产品失败 |

有外部结果要求时，HTTP2xx、提交成功或响应非空均不够。

## 输出约定

逐执行给紧凑证据表：

| 字段 | 必须内容 |
| - | - |
| 环境 | 精确环境及仿真/生产类型 |
| 执行模式 | 平台API+本地、本地API+本地、仅本地证据 |
| 平台资产 | Case、场景/参数ID及适用修订/Release |
| 关联 | 脱敏请求/业务/任务/文件ID、标记、trace/logID |
| API结果 | HTTP、业务、异步终态、断言 |
| DB证据 | 工具/实例别名、查询时间、数量、关键字段、子明细一致性 |
| 日志证据 | 服务链、决定性跳过/拒绝/失败/成功及脱敏下游响应 |
| 副作用 | 新对象、清理或明确保留 |
| 综合结论 | Passed/Failed/Skipped/Blocked/Inconclusive |
| 后续 | 产品缺陷、环境配置动作、平台缺口或无 |

平台通过但外部失败须两者都说明，不改写平台报告、不伪造断言、不称整体通过。

## 完成检查

核实精确环境/模式；平台操作遵循最新适用Skill；没给平台加受限SQL/连接；本地DB始终只读；需要时本地API已明确授权；请求与确认Case/权威契约一致；异步文档终态或明确超时；查询用精确本轮ID和确定排序；可用时用trace/日志查缺行；秘密已脱敏；副作用和清理/保留已汇报；综合结论涵盖API加全部外部证据。
