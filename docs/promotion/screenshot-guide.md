# 宣传截图与脱敏规范

宣传截图的目标是证明真实能力和解释操作链路，而不是展示尽可能多的菜单。每张图只表达一个主题，并保证读者无需放大多次才能理解。

| --- | --- | --- | --- | --- |

| 02 | API 用例编排 | 技术文章、OSCHINA | 步骤、场景、提取与断言结构 | URL、Header、Cookie、Token、请求与响应业务数据 |

## 演示数据标准

- 项目统一命名为“电商演示项目”或“Demo Project”。
- 产品和模块使用“商城 / 用户中心 / 订单中心”等通用虚构名称。
- 域名只使用 `example.com`、`example.org`、`example.net` 或本地演示服务。
- 用户使用 `demo_user`、`tester_a` 等虚构名称。
- 数据库、表和字段使用 `demo_db`、`demo_order`、`order_id` 等示例名称。
- Token、Cookie、密码、Authorization、密钥和连接串不做局部遮盖，必须整体替换为明显的占位符。
- 不出现公司名、客户名、工单号、员工姓名、群聊、邮箱、手机号、IP、主机名和本地绝对路径。

## 录制前设置

1. 新建完全独立的演示项目和演示账号，不从真实项目复制后再逐项删除。
2. 使用无痕演示数据，提前准备一条成功记录和一条可解释的失败记录。
3. 清空浏览器自动填充、历史下拉项、下载记录和开发者工具中的历史请求。
4. 关闭桌面通知、聊天软件、密码管理器提示和无关标签页。
5. 使用 1920×1080 或更高分辨率，页面缩放保持文字可读。
6. 截图前检查右上角用户信息、面包屑、筛选项、表格列和弹窗背景。

## 截图后复核

至少由另一人按原图分辨率检查一遍，重点放大以下区域：

- 地址栏、标签页标题和浏览器收藏栏；
- 页面右上角头像、姓名、环境选择与通知；
- 表格横向滚动区域和弹窗背后的页面；
- 请求头、响应、日志、SQL、错误栈和下载文件名；
- 图片 EXIF 或其他可能包含作者、位置、设备信息的元数据。

对敏感内容优先重录，不依赖模糊或马赛克。必须遮挡时使用不透明色块，并确认导出结果不可通过调整透明度恢复。

## 当前素材状态

仓库根目录的 `功能演示.gif`、`UI执行演示.gif` 和 `API执行演示.gif` 来自历史版本，可继续作为兼容性预览，但不应作为最新版界面证明。新宣传稿发布前应补齐上表 01～05，并替换其中可能暴露真实项目、人员或业务名称的旧画面。

由于仓库约束禁止使用浏览器控制工具自动获取截图，本轮文档不会伪造或自动操作页面生成产品截图；应由维护者在完全脱敏的演示环境中按本规范录制。
