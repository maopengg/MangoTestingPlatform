# 场景建模

创建修复复用模板、组合多表、解依赖循环、缓存输出或绑定API/UI时读取。

## 从业务状态开始

用业务话定义前置，再用真实schema和DDL/ORM/mapper/DTO/service映射表关系，识别根/子/关联、外业务键、租户、合法枚举、软删审计；插入清理顺序；Case需输出值；哪些必须真实API/异步引擎/签名/第三方，工厂仅表达DB状态。

每有意义实体状态一复用模板。`usage_scope=1`只给完整可选场景，`usage_scope=2`内部子/中间。`is_default`为依赖默认，与scope独立。

## 业务键与共享读取检查

保存共享读取对象的实体规则、模板或 Case 覆盖前，在现有建模/审计证据中记录，不臆造平台字段：

| 对象及原测试目标 | 实际读取作用域/条件与代码位置 | 业务键来源及新建/复用依据 | 消费者及存续时间 | 清理归属 |
|---|---|---|---|---|

1. 从生成项和递归依赖识别预置身份、保留 key、内置 code、版本链和非主键引用；查看创建、读取、更新、删除代码，以及缓存/索引键。不能只看 INSERT 是否成功或数据库唯一约束。
2. 对比实际查询中的租户、应用、业务类型、父对象、业务键、状态和版本条件。若代码只按租户加业务键读取，仅更换表单、主键或名称不能隔离；若代码证明完整作用域能够区分，相同键才可能合法共存。检查有效/发布状态是否会把临时对象暴露给共享查询，不能为了前置可用就直接设为全局可见状态。
3. 按入口 Skill 决定复用还是创建：只读复用须满足原场景和关联约束；自定义对象按真实创建规则生成唯一键并统一传递。需要系统预置行为时，不能改成自定义键后仍称覆盖不变；需要版本复制时不能伪造另一份独立预置对象。
4. 用获准的有界只读查询核验资格、已有冲突及本轮输出，避免宽表扫描；查询时无冲突只是补充证据，不能替代代码作用域检查或防止并发竞争的设计。必要验证只在已授权安全范围执行，不为证明隔离擅自修改共享开关或进行并发压测。
5. 检查实体默认规则、模板、父项、Case 覆盖后的最终值，以及公共资产的全部直接/递归引用和消费表达式。修复保存完整目标列表，保留无关配置；无法安全覆盖全部受影响消费者时，明确未核验项和剩余风险，不仅凭单 Case 通过宣布整体完成。

隔离不足时先修复方案，停止受影响的真实造数，不删除证据或静默停用其他 Case。原主键归属清理要求继续适用，但不能替代执行期间的读取隔离。

## 字段归属和覆盖

通用稳定生成放实体，状态差异放模板 `field_overrides`，父场景提供放 `items[].field_overrides`，单Case差异放绑定。不无谓多层复制；最窄优先，预览不符查全层，自增规则各层有效。

数据库自动生成字段默认跳过的规则同样覆盖所有层级及插入后回写，不因模板或 Case 的非空需求显式补值。保存前核对最终合并载荷及实际 INSERT 是否省略这些列；后续只消费数据库生成后的真实值。应用层默认与普通业务 DEFAULT 按入口 Skill 区分，不能把应由调用方准备的必需字段误跳过。

精确业务状态优于任意随机，随机串格式允许以AUTO起，用 `AUTO${{...}}`；严格格式/非串豁免记理由。随机须合法且不误进其他分支，用 `list_test_data_methods` 并保存前预览。

枚举每层保 `generator_type=9`及权威带类型集合，特定值用 `mode=fixed`，不普通固定。选项改变配套必需/禁止/默认/解释时，每合法组合明确成模板状态整体预览，不在配套要求不同选项间随机。

## 依赖

两种不同模式：

1. 实体依赖：`generator_type=11`、`dependency_entity_id`、`field`及可选 `template_id`/策略，runner另准备实体/模板消费输出。
2. 同执行节点：场景项type11用 `source_node`/`source_field`，复用根或前兄弟已插值，不再建依赖行。

父子外键用DB生成ID时采用同执行引用：

```json
{
  "risk_state_id": {
    "generator_type": 11,
    "generator_config": {
      "source_node": "root",
      "source_field": "id"
    }
  }
}
```

source_node可root或 `item:<item ID/name>`；只引用根/排序在前兄弟，不自指或指后项，按真实插序排列。

## 循环与插入后回写

两行互引数据库生成ID，不预生ID，靠可空字段破环：

1. 首节点循环目标省略（generator_type0）。
2. 次节点引用首节点实际ID。
3. 用 `post_insert_updates` 把次节点实际ID写回首节点。

```json
[
  {
    "target_node": "root",
    "target_field": "current_score_result_id",
    "source_node": "item:评分",
    "source_field": "id",
    "sort": 10
  }
]
```

目标INSERT时须可空且跳过生成。平台自动生成按主键安全更新，不向回写放原SQL、表名、自定义WHERE；存启前检查验证和SQL模板。两列插入时都必须非空则无schema/流程支持不能安全表达，停止，不编ID或关约束。

## 输出与缓存

`output_config`只暴露Case/后续需值，尤其DB返回ID/稳定业务键；核详情cache_prefix/cache_keys，表达式遵当前schema，通常 `${{配置名.字段名}}`。名称稳定无歧义，不复制预览/旧执行ID入请求；模板/绑定改名查全部消费表达式。

## 自动化绑定

绑定前先查询已有配置，避免重复创建。通过 `get_data_factory_schema` 核对 `source_type`：1 为 API Case，2 为 UI Case，3 为 API 接口场景参数。

普通前置一律 `1=执行结束`，`2=手动清理`/`3=不清理` 仅用户明确保留且记录自动清理违目标原因时允许；有持久行的保留例外需归属、保留时长及最终清理才算可复用完成。按依赖业务序绑定，再用保存覆盖和环境 `preview_data_factory_case_config`。

Case须消费生成缓存，断言证明目标分支；预览造行不喂请求不是完成。

API创建数据在工厂记录之外，逐场景保归属清单：消费节点/键；API可造的表行含子关联审计业务异步；每行响应ID/关联ID/本轮唯一键；Case后置动作及依赖安全删除序。

跨创建来源有依赖时，先清理本轮下游资源与关联，再清理上游资源。优先使用响应 ID，无 ID 时用已验证的本轮唯一键及租户。共享名称、时间或上游标识不能单独证明下游归属。

产品删除API能失败安全Case后置才用，否则非生产支持的Case级后置SQL。响应后处理不能兜底，失败可能跳过。删除幂等，不让工厂发现任意相关表、不因外键错自动级联；下游清理缺或不可证不发布。

## 场景验收

启用/绑定前：根和所有项预览无缺；所有有限域保完整typed枚举/标签，选择及配套合法；外键指本轮正确行；DB生成ID插入省略后消费；回写验证且限定主键；缓存与请求变量一致；先子关联后根；普通执行结束清理、保留例外有责任时长精确行与最终路径；消费写Case保存覆盖全部API后代的失败安全后置且先于工厂；只有完整可选对象才usage_scope1。
