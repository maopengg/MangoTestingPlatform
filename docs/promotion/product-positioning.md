# 芒果测试平台产品定位与传播口径

## 一句话定位

芒果测试平台是一套可私有部署的质量工程平台，从研发协同、功能测试，到 API、UI、Pytest 和性能自动化，再到测试数据、调度执行、质量效能与 AI，形成一条可追踪的测试闭环。

## 30 秒介绍

芒果测试平台面向需要持续建设质量工程能力的研发和测试团队。平台将迭代、需求、设计、功能用例、缺陷与 API、UI、Pytest、性能测试资产放进同一个协作空间，并通过数据工厂、任务调度、独立执行器、质量报告和 MCP 串起执行与反馈。常规场景可以低代码配置，代码型测试仍可保留原有表达能力，AI 则在权限和审计边界内使用真实平台资产。

## 版本口径

- **公开仓库当前能力**：API、UI、Pytest、数据工厂、定时任务、执行器、报告、监控与 MCP 等主链路，可按公开文档部署体验。
- **最新版能力预告**：研发协同、性能测试、模块覆盖、Mock 服务、质量效能、UI 智能定位与自愈、灰度管理、统一运维审计等能力已在最新版建设，可在社区文章中公开介绍，并注明会按版本逐步开放。

## 核心价值

### 1. 研发与测试形成协作闭环

以迭代和需求组织开发设计、功能用例、测试计划与缺陷，功能用例可以绑定自动化资产，让“需求覆盖了什么、执行结果如何、还有哪些风险”有统一入口。

### 2. 自动化资产统一管理

API、UI 和 Pytest 不再分散在个人脚本、配置文件和多套工具中。平台按照项目、产品、模块和环境组织资产，便于团队协作、回归执行和历史追踪。

### 3. 测试数据进入执行闭环

数据工厂支持逻辑数据源、环境绑定、实体、字段生成规则和状态模板。用例执行前可以自动准备数据，执行中引用生成结果，结束后按策略清理，减少手写前置 SQL 和环境硬编码。

### 4. 执行过程可追踪

平台统一记录任务状态、请求响应、断言结果、失败信息、日志和截图。定时任务、远程执行器和 API Worker 让自动化从“本机能跑”变成团队可持续运行的服务。

### 5. AI 能力落到真实测试资产

平台通过 MCP 开放项目上下文、自动化用例、数据工厂、执行任务和测试报告等能力。AI 不只生成一段孤立脚本，还可以在明确权限和审计边界内查询资产、辅助配置、触发执行并分析结果。

## 目标用户

- 正在从个人脚本转向团队化自动化建设的测试团队
- 需要统一管理 API、UI 和 Pytest 资产的测试开发团队
- 测试数据准备复杂、跨环境复用困难的业务团队
- 希望私有部署测试平台的中小型研发组织
- 正在探索 AI Agent 与质量工程结合方式的团队

## 差异化表达

对外介绍时优先讲以下四点：

1. **研发质量闭环**：迭代、需求、设计、功能用例、测试计划、缺陷和自动化结果互相关联。
2. **数据工厂**：不是只管理用例，还把测试数据的生成、引用和清理纳入执行链路。
3. **智能自动化**：API 模块覆盖与 Mock、UI 智能定位与自愈、性能场景和执行器容量形成更完整的自动化矩阵。
4. **MCP 与 AI**：不是只生成测试脚本，而是让 AI 连接真实的测试资产、执行任务和报告。

## 不建议使用的表达

- “行业第一”“完全替代所有测试工具”等无法验证的绝对化描述。
- “所有测试都不需要写代码”。API 和 UI 的常规场景可以低代码配置，但 Pytest、自定义函数和复杂扩展仍可能需要编码。
- 只罗列功能数量，不说明解决的问题。
- 把 AI 描述成完全自主且无需审核的执行主体。
- 与其他开源项目做贬低式比较。

## 推荐标语

主标语：

> 让测试资产、测试数据和自动执行真正连成一条线。

备选标语：

- 从用例编排到数据准备，让自动化测试形成闭环。
- 不只管理脚本，更管理可持续运行的质量资产。
- 让 AI 连接真实测试平台，而不只生成孤立代码。
