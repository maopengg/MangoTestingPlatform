# 数据工厂创建与修复

本 Skill 是 AI 操作数据工厂的约定。目标不仅是启用实体，还必须建立与真实表和代码业务语义一致的模型，形成环境正确、可复用的场景：生成值满足业务状态，缓存输出能供自动化 Case 使用，数据可以安全清理并验证。

通过目标部署的测试平台 MCP 操作。禁止通过 Django ORM、直接编辑平台数据库、内部 HTTP 或临时 SQL 绕过 MCP 读写平台元数据。首先调用 `get_data_factory_schema`；示例与实际契约不一致时，以返回的 schema 和当前工具签名为准。

## 绝对安全规则

- 创建/修复数据工厂本身不授权创建或发布无关 API 资产。涉及已授权 Case 工作时，Case 完整验证后最多提交预发布，包括定时报告修复，正式发布均交用户/产品负责人；必要 API Info 按 API Case Builder 自检、验证并生成修订后，有接口发布权限即可直接发布，不走 Case 审批。权限不足不阻断独立工厂/Case 工作，保留真实状态交接；清理门禁不变。
- 实体生成器、模板字段、父项、查询/脚本、输出假定、清理及 Case 覆盖值不得写死环境业务数据。租户、用户、组织及已有前置通过当前环境全局/公共变量、授权上下文、合格只读查询或本轮生成依赖获取。保留运行表达式，不保存解析后的固定 ID/名称，不回退到历史值。允许合法枚举默认值和代码常量，但不允许固定外键/业务键引用。预览及最终 Case 回读核验资格、归属和运行来源；工厂只清理其本次创建的数据。
- 读 schema 或改资产前先确定项目产品、模块、逻辑数据源及具体 `test_env`，禁止拿一个环境的 schema 修另一个环境。
- 测试平台禁止数据工厂和生产 SQL 连接。不得在生产环境绑定、配置、执行预览、执行或清理工厂，不得用平台 SQL 查询/修复生产业务数据。生产回归 Case 不含工厂、生产数据库连接或 SQL。本地已有合法生产连接时，只允许在平台外进行任务相关只读 `SELECT` 诊断；禁止生产数据、schema、权限写入，不将连接、凭据或 SQL 复制进平台资产。
- 工厂行创建与删除使用 SQL（操作类型 `2`）；模板可通过 `cleanup_resources` 配置关联 ES 的精确验证或条件删除。不得声称已支持任意 API、自定义函数、多文档或 Redis 自动清理；数据源执行审计不等于已配置清理。
- 除修复确需变更外，保留已有生成规则、模板、依赖、绑定、输出和覆盖；禁止只为验证通过删除或停用资产、字段、项或 Case。
- 所有随机字符串在格式和业务契约允许时必须以大写 `AUTO` 开头，如 `AUTO${{str_lowercase(10)}}` 或 `AUTO_${random}`，包括随机名称、标题、描述、编码、邮箱等。数值、日期、布尔、数据库生成 ID、枚举、严格 UUID/手机号/身份格式、签名、哈希、固定协议值和权威固定字面量不强加前缀；随机字符串确需豁免时记录理由。
- 更新前读取完整对象。`items`、`post_insert_updates`、`output_config`、`cleanup_resources` 及字段替换列表是整表替换，必须提交完整目标列表。更新模板时省略 `cleanup_resources` 保留原规则，传 `[]` 清空后续执行规则，不改变历史执行快照。
- 模板执行和清理会增删真实业务数据，必须先执行对应影响预览、核对实际影响并原样传递 token/确认文本。用户已授权在指定非生产环境创建/修复并完整验证时，该范围的工厂执行和执行结束清理已获授权；用户已授权处理本轮残留时，也包含同范围、已证明归属资源的正式精确补偿，不再逐条询问“是否允许清理这一条”。工具要求新预览或确认凭据不等于必须重新取得用户授权。只有尚未授权或实际操作超出原环境、执行/资源范围及清理方式授权时才再确认；归属不明时先停止并补证，不能靠用户批准放行。授权范围判断及补偿协议见 [数据源与ES清理](references/datasource-usage.md#补偿授权范围)。配置预览不写业务数据，可正常使用。
- 工厂只拥有执行记录内的行。API/UI 消费工厂数据又创建持久子表、关联、业务、审计或异步数据时，Case 必须保存独立、失败也执行的后置清理。先清理 Case 创建的后代，再清理工厂数据；不得假定删除工厂根行就足够发布。
- API 新建 SQL/ES 资源的登记、数组身份映射、负向创建、重复名称及历史清理恢复，必须读取 [API 资源清理编写教程](../mango-api-case-builder/references/api-created-resource-cleanup.md)，并查询当前 `get_api_case_resource_cleanup_schema`。使用 Case 的 `resource_cleanup`，不是模板的 `cleanup_resources`；不能把 API 数据登记成工厂执行所有物。具体配置只维护在该教程，不复制另一套规则。
- SQL 零残留不能证明 ES 已清理。涉及索引副作用时，执行前读取 [关联 ES 清理](references/execution-and-acceptance.md#关联-es-清理)，核实文档 ID 来源与所有权快照；SQL 主键与 ES 文档 ID 不同时显式配置 `document_id_field`，禁止猜测、缺值回退或接管无快照的历史文档。

## 业务身份与共享作用域隔离

唯一主键、随机名称、AUTO 前缀、按主键精确清理和最终零残留，都不能单独证明业务隔离。本轮创建的数据，也可能在存续期间被其他页面、Case 或异步任务读到。

创建或修复字段定义、字典、业务规则等可能被共享读取的对象前，必须按实际代码核实业务身份和读取作用域，重点追踪非主键查询、有效/发布状态、版本选择、缓存及索引匹配条件。数据库唯一索引、表单/父对象外键只提供线索，不能代替所有相关消费者的实际过滤条件。建模证据和检查顺序见 [场景建模](references/scenario-modeling.md#业务键与共享读取检查)。

- 不得在相同共享读取作用域内，用不同主键或显示名称重复创建系统保留 key、内置 code 或已有业务身份的“独立临时对象”。若代码明确允许跨表单、版本或其他作用域复用相同业务键，须证明相关读取能够正确区分，不能一律按字符串相同禁止，也不能仅凭创建合法就认定读取安全。
- 系统预置对象优先只读复用，核对环境、租户、归属、类型及原场景资格；复用行不属于本轮创建数据，不得加入清理目标。代码要求版本复制、初始化或迁移时遵循真实业务流程，不擅自跨表单复用，也不直接伪造预置身份。
- 自定义对象使用符合真实创建代码和产品契约的运行期唯一业务键，关联与消费步骤复用同一输出。不能通过随机化保留 key、改成自定义对象或更换作用域，悄悄改变原测试目标、分支和断言能力。
- 保存、启用、绑定或执行前，复核完整生成载荷及所有覆盖层。实际读取作用域会冲突、复用资格不符或隔离证据不足时，先修正受影响的生成/依赖方案，不执行该部分真实造数；按现有证据流程继续调查，不凭猜测宣称安全。不得靠取消清理、永久保留冲突行、修改共享配置/权限或未经授权新建租户来绕过问题。
- 修改公共实体或模板前反查直接/递归父模板、覆盖、输出和消费 Case，记录受影响范围及逐项验证结果；只验证一个消费 Case 不代表公共资产整体修复完成。不得自动改动授权范围以外的消费者。

这些检查在创建、修复和获准存量审计时执行，不代表 Skill 更新后平台会自动扫描所有已有资产或新增持续告警。审计只报告已查范围与证据，未查部分不能称安全；本节不扩大原有配置、角色、权限及环境禁写边界。

## 数据库自动生成字段默认跳过

编写、同步或修复字段规则时，真实数据库负责自动生成的字段，默认使用 `generator_type=0`（跳过），INSERT 省略该列，由数据库生成。包括已确认的自增列、生成/计算列、数据库自动生成的 UUID/序列值，以及由数据库默认表达式或触发器自动维护的字段；不是只处理主键。

必须以目标环境的真实 schema、已执行 DDL 和触发器定义核实生成行为，不能仅凭字段名、旧模板或 ORM 的应用层默认推定数据库会生成。跳过表示不出现在 INSERT 中，不是显式传 `null`、空串、固定值或 AI 生成的替代值；不得因非空校验提示而为自动生成列补值。实体、模板、父项、Case 覆盖及插入后回写都须遵守，发现旧覆盖冲突时修正并回读最终规则。

数据库生成字段需要被后续步骤使用时，只输出插入后真实返回/回读的值，不预造；当前平台无法获取必需生成值时报告缺口，不伪造输出。普通业务列仅有 `DEFAULT 0/1` 等兜底值，不自动视为禁止赋值的生成列：默认状态确实由数据库负责时跳过，场景须显式提供合法状态时按代码契约配置。应用层生成而数据库没有对应能力的字段不能跳过。有限域元数据仍保留，生成归属优先决定是否跳过，再为需要工厂赋值的字段选择枚举等生成器。

## 数据库生成 ID 的不变量

这是硬门禁，不是建议。

创建、同步、修复、启用、完成性预览或执行实体/模板前，调用具体环境的 `get_data_factory_table_schema` 检查真实主键。

字段同时满足 `primary_key=true` 和 `autoincrement=true` 时：

- 保留 `autoincrement=true`、`generator_type=0`，INSERT 不传该列，由数据库生成。
- **禁止自行填写或生成此 ID。** 即使预览通过或数据库允许显式 ID，也禁止随机整数、固定值、UUID、雪花 ID、测试数据表达式、依赖值、缓存值、API 值及任何非零生成器。
- 实体字段、模板 `field_overrides`、父级 `items[].field_overrides` 和 API/UI Case 绑定覆盖均受此限制。
- 仅插入成功后通过 `output_config`/缓存输出 ID。子行用同执行节点引用，如 `source_node=root, source_field=id`，引用实际 ID。
- 执行器不能返回或传递生成 ID 时停止并报告能力缺口，不得编造 ID 绕过。

非自增主键只有在真实 schema 与后端契约证明调用方必须提供时，才设置显式生成器。

## 与代码一致的实体不变量

真实表 schema 确定物理结构。匹配运行版本的代码和映射用于确认实际赋值、校验、读取及副作用，已确认的需求或契约用于判断预期语义。两者冲突时，先核对版本、环境和适用条件，记录差异。冲突未解且会影响合法数据、隔离或用例预期时，暂停受影响的配置启用，并继续独立项。schema 同步只生成草稿。

启用前逐字段检查最接近的证据：已执行 DDL/ORM 映射、注释/默认值/索引/外键、后端枚举/常量、DTO/schema 校验、mapper/repository 转换、service 条件与状态迁移、维护中的 API/业务文档。记录足以解释生成器及豁免的证据，重点核验有限取值、外键/业务键、租户、逻辑删除/状态、JSON、时间、审计身份、数据库默认值及跨字段依赖。

数据库或应用负责默认/生成值，显式插入会绕过其行为时，使用 `generator_type=0` 省略字段。租户、创建/更新人、组织、账号等从当前上下文或已证明依赖获取，不因一次预览成功就固化共享 ID。调用方提供的唯一键/业务键遵守代码格式、范围与防冲突规则，仅格式允许时带 `AUTO`。

权威来源定义有限取值即视为枚举，即使数据库类型是 `INT`、`TINYINT`、`VARCHAR` 等而非 `ENUM`。`*_type`、`*_status`、`*_state`、`*_mode`、`enabled`、`valid`、删除标记都必须明确判断枚举/标记；名字只是调查线索，不能据此编造选项。

已证明的枚举必须：

- 保存完整、保留类型的 `enum_values` 和可读 `options`；
- 使用 `generator_type=9`，不得用普通固定值或随机数/字符串；
- 稳定基础状态用合法默认值的 `mode=fixed`，仍是枚举，不是 `generator_type=1`；
- 仅当每个选项都适用于同一可复用状态、不会进入另一业务分支或要求不同配套字段时，才用 `mode=random`；
- 场景差异放模板或 Case 覆盖，保留枚举生成器及允许集合；
- 新证据证明有限域时，将旧普通固定规则迁为枚举；“保留已有规则”不保护语义分类错误。

schema 已建议 `generator_type=9` 时，需证据证明字段并非有限域才可降级。实际代码确认的枚举缺失时补全字段载荷。旧注释、推断或模板与已核实的事实冲突时，记录并更正过时元数据。已确认契约与运行行为冲突时，按本节冲突规则处理。

### 穷尽证据后再提问

不得为了创建或启用实体降低标准。宣布字段不明确前，先穷尽用户当前与已确认上下文、附件/示例、真实 schema/注释/约束、提供或可访问的仓库修订、维护中的技术/业务文档。按表名、ORM/model、mapper/repository 语句、列名、枚举、DTO 字段和 service 用法搜索，同时追踪建表/映射和实际赋值、解释字段的读写路径。

提供或可访问的代码包含表定义和创建/使用链路时，AI 必须自行解析，不要求用户重述代码已能确定的字段含义、枚举、默认值、关系或组合。继续追踪引用、常量、转换器、校验、测试和调用方；一时找不到答案不允许降级为普通固定/随机值，也不允许过早提问。

查完上下文、附件、schema、代码和文档后，只有缺少决定合法数据、隔离或用例预期的证据，或仍需外部业务决定时才提问。说明具体字段、已查证据及影响。受影响配置在问题解决前保持停用。

## 流程路由

- 涉及 SQL／ES／Redis 的职责、派生索引、局部 ES 文档或历史补偿：读 [数据源与ES清理](references/datasource-usage.md)。不因业务依赖 ES 就创建独立 ES 工厂或假 SQL 实体。
- 创建实体、同步 schema、修复无效模型、工作台模型待办：读 [实体修复与启用](references/entity-repair.md)。
- 新模板、多表对象、依赖、同执行节点、循环关系、输出和 Case 绑定：读 [场景建模](references/scenario-modeling.md)。
- 真实执行、清理、清理失败修复及最终验收汇报：读 [执行与验收](references/execution-and-acceptance.md)。

必须读取本次适用的全部引用；字段修复影响模板时，实体和场景两份都读。

## 通用工作步骤

1. 建立基线：资产 ID/名称、状态/配置状态、表名、数据源/环境绑定、字段、模板、递归父模板、Case 绑定、近期执行，适用时含工作台待办 ID。
2. 按最接近的权威证据恢复业务语义：真实 schema 决定结构；已执行后端 DDL/ORM/mapper/DTO/service 决定枚举、租户、默认、关联、跨字段与合法状态；已有有效模板提供本地惯例。启用前建立上述代码一致字段模型，不编造必填值或外键目标。
3. 数据库可表达前置优先用可复用实体/模板；不可替代的流程迁移或外部副作用才用正常产品 API。普通可复用自动化必须执行结束清理；手动或不清理须有用户明确要求及保留理由。
4. 启用前逐层预览完整字段值、由子至父的模板、Case 绑定，修正缺字段、类型错误、枚举降级、非法组合、依赖未解析或必需输出为空的根因。
5. 通过已验证的 MCP 状态操作启用，不绕过验证。改实体后递归验证直接与上游模板，仅实体恢复不算完成。
6. 涉及工作台待办时先修底层资产，调用 `refresh_workbench_todos` 再查询；不得手动关闭可客观检测的无效模型风险。
7. 对每个消费 API Case 建数据归属清单：工厂项、API 创建后代/关联、定位它们的本轮精确标识、删除顺序。通过 MCP 读取完整 Case，确认 Case 创建行已有 Case 级后置清理，才满足发布前提。

## 完成标准

更新成功或状态启用本身不代表完成，至少证明：

- 字段名称、顺序、数据库/平台类型、可空、主键、自增和长度/默认值语义匹配所选环境真实 schema。
- 字段规则匹配代码：有限域使用完整带类型及可读标签的枚举规则；外键/业务键有已证依赖；状态、逻辑删除、租户、审计、JSON、时间、默认及跨字段反映实际用法。禁止把权威枚举表达成普通固定或随机值。
- 不存在本可由上下文、附件、schema、代码或文档解决却未解决的字段；真正外部业务决定明确报告并保持停用。
